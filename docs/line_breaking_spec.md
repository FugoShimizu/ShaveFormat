# Shave Format 行分割仕様

本書は `FormatIR` の折返候補の所属，評価順及び幅に依る選択を規定する．`LineBreaker` は原文又は解析木を書き換えず，宣言された選択肢を解決して `BrokenIR` を返す．実装の到達状況，補助関数名及び内部ファイル構成は規定しない．

整形全体の契約は [整形仕様](formatter_spec.md)，書式と表記は [コーディング規約](../CODING_STANDARDS.md) に従う．本書の節は「本書」，整形仕様の節は「整形仕様」，コーディング規約の節は「規約」として参照する．

# 第１章 適用範囲と責務

## 1.1 責務の分担

| 工程 | 本書に関係する責務 |
|---|---|
| `SourceProjector` | 文境界，密着，改行禁止及び逐語領域を構文事実へ変換する． |
| `SyntaxNormalizer` | 幅に依らない括弧・本体・宣言等を正規化する． |
| `Canonicalizer` | 構文上の役割から `SoftBreak`，`HardBreak`，`Group`，`IfBroken` 及びアンカーを生成する． |
| `LineBreaker` | 不変の `MaxChars` を唯一所有し，文字数を測って全ての選択を解決する． |
| `CodeLayout` | 解決済の範囲と改行へインデント・空行を具体化する．折返位置を選び直さない． |

境界・生成トークンの言語毎の差は `FormatIR` の値で表し，全言語に共通の選択手順を用いる．平坦時の空白は [トークン間空白仕様](token_spacing_spec.md)，情報境界は整形仕様 3.5 に従う．

## 1.2 対象言語と適用範囲

全対象言語を同じ経路へ通し，意味を保って折れる境界を構文上の役割から生成する．Python の複合文本体は必須展開とし，単一文でも１行形を生成しない．行幅が `0` の場合も必須改行を消さず，幅だけを理由とする分割を省略する（整形仕様 2.1, 6.4）．

# 第２章 候補とグループの構成

## 2.1 構文上の所属

分割候補はトークン其の物ではなく，構文の役割が定める境界である．パーサーがトークンを名前付又は無名の何方として出すかを，候補の可否又は優先順位の根拠にしない．

`SoftBreak` には平坦時の表現と折返時の表現を定める．前者は密着又は必要な空白，後者は合法な改行とする．文を終える必須改行及び標準構文の必須境界は，任意の候補でなく `HardBreak` 又は対応する制約で表す．コメント経路のディレクティブの適用条件から，分割候補・グループ・必須境界を追加しない（整形仕様 4.5）．

同じ構文単位で一緒に採否を決める境界を，１つの `Group` に所属させる．例えば実引数の並びの開きの後，要素を区切るカンマの後及び閉じの前は同じグループとする．各要素の内側の呼出・式・配列は別の子のグループを持つ．

次の所属を明示する．

| 構文 | グループの構成 |
|---|---|
| 実引数・仮引数・配列・オブジェクト等 | 開き・区切・閉じを対応付ける．空の並びの内部には任意の候補を作らない． |
| 二項式・三項式・代入式 | 当該の演算を構成する境界を同じグループにする． |
| 初期化文を持つ見出 | 初期化・条件・更新を区切るセミコロンを見出のグループへ所属させる．初期化文の終端と云うパーサー側の親子関係を引き継がない． |
| メンバ参照・後置連鎖 | 呼出の実引数のグループと，受手から続く参照のグループを区別する． |
| 分割可能な文字列の並び | 言語が別のトークンとして並べれる要素の境界を候補にする．リテラル本文の内部は対象にしない． |
| 単一文の制御本体 | 同行の本体と，必要時のラッパー・改行を同じ意味の選択肢として表す． |
| JSX / HTML の属性 | 属性間と合法な閉境界に候補を置く．属性値・本文の内部と区別する． |
| CSS / SCSS の要素・演算 | カンマで区切る並び，合法な演算及び条件の境界をグループにする．セレクタ又は値に新しい意味上の空白を作らない． |

隣接文字列では，先頭の子より後の境界を対象とする．Ruby の `%w` / `%i` の様に要素の並びとして扱う物では先頭要素の前も候補に出来るが，開始記号・内容・終端の意味を保持する．Ruby の隣接文字列連結は，本書 2.3 の分割禁止を優先する．

`NodeId` とアンカーはグループの平坦形・展開形の何方にも対応付ける．グループを選んだ後に原文の位置又は再解析で所属を探し直さない（整形仕様 3.2, 6.1）．

## 2.2 折返の側

折る場合にトークンを前行へ残すか次行へ送るかは，`Canonicalizer` が構文上の役割と共に表す．行幅を測ってからトークンの役割を推測しない．

| 役割 | 折返位置 | 代表例 |
|---|---|---|
| 開きの区切 | 後 | `(`, `[`, `{` |
| 要素・見出の区切 | 後 | `,`, `;` |
| 二項・三項・代入・アロー | 後 | `+`，`&&`，`=`，`?`，`:`，`=>`，語の演算子 |
| 閉じの区切 | 前 | `)`, `]`, `}` |
| メンバ参照・スコープ | 原則として前 | `.`, `?.`, `->`, `::` 等，参照を表す物 |
| Go のメンバ参照 | 後 | `.` |
| Go の節見出 | 前又は必須境界 | `case`, `default` |
| Ruby の節の境界 | 前 | `elsif`, `when`, `else`, `rescue`, `ensure`, `end` 等 |

此の表はテキストの一括分類ではない．前置の `-`，型の `*`，捕捉の `&`，閉じを持たない範囲等を，二項演算子又は通常の区切として折らない．先頭の `const` / `new` 等も，語である事だけを理由に候補にしない．

複数行の行頭へ置いた閉括弧の後は，次も閉括弧なら次行へ送り，其れ以外は同じ行へ続ける．`},`，`};`，`} else`，`} catch`，do-while の `} while`，宣言名，`from`，代入，型アサーション及び後置連鎖も含め，接続した後の行の幅が上限以下なら接続し，超える場合は当該グループを展開する（規約 3.2，整形仕様 6.3）．

## 2.3 候補にしない境界

分割不能な領域が行幅を超えても，其れだけを理由にファイル全体を見送らない．

| 対象 | 分割を抑止する範囲又は条件 |
|---|---|
| 逐語領域 | リテラル本文，地の文，データ，許容したエラー領域等の内部． |
| 空の括弧 | `()` / `[]` / `{}` の内側．空行を作っても幅を減らせない． |
| 単項演算・型の接尾記号 | 被演算子・型との密着を壊す位置．Swift の後置 `?` / `!` 等を含む． |
| 仮引数の囲み | Rust / Ruby の `\|` の直後を通常の二項演算子の候補にしない．内部のカンマ等は別に扱う． |
| プリプロセッサディレクティブ | 連結した C / C++ のディレクティブ，C# の `#pragma` 等の１論理行の内部． |
| 型注釈と初期化子を持つ宣言 | Rust の束縛，Kotlin の戻値型と式本体等で，型の `:` を初期化の `=` と一律に同じ分割グループへ入れない． |
| C++ のラムダ捕捉 | 捕捉の `&` / `=` / `*` を名前等から切り離す位置． |
| Swift の import | 完全修飾名の内部． |
| Swift の見出の束縛 | 条件内の `=` の直後を，条件の区切のカンマと同じグループにしない． |
| PHP のキャスト・地の文 | キャストの不可分範囲と，出力本文を変更するタグ境界． |
| JSX の本文 | 対象処理系で同じ内容を保持出来ない行端と，属性の無いタグの内部． |
| TypeScript の省略可能な名前 | `name?: T` の `?` と型注釈を分断する位置． |
| TypeScript の比較と型引数 | `a < b >` の後等，改行で別の文又は型引数の読みへ変わる位置． |
| Ruby のヒアドキュメント | 開始トークンを含む論理行の全体．開始行の途中の折返でも本文の起点が変わる． |
| Ruby の修飾子 rescue | 改行で独立した rescue 節へ変わる内部境界． |
| Ruby の隣接文字列連結 | 別の文又は別の値として読まれる境界． |

パーサーが演算子をノードの末尾へ取り込んだ等の誤読は，入力適応と投影で解決する．中核へ誤読を残して「元のテキストを見れば折れる」候補を作らない（整形仕様 4.2, 4.3）．

# 第３章 選択の確定順

## 3.1 全体の順序

１回の `Resolve` は次の順で行う（整形仕様 6.4）．

1. 構文・構造・逐語内容に関する必須条件を満たす選択肢だけを残す．
2. 分割可能な統合宣言のグループを確定する．
3. 条件付の波括弧・継続括弧・末尾カンマ・空白の値表現を含む決定単位と順序を，本書 3.4 に従って定める．
4. 各決定単位を１度だけ評価し，通常の分割グループには本書 3.3 の測定条件を適用する．

グループの基準順位は，構文の並びを左から右へ辿り，子のグループを親のグループより先にする**後行順**とする．左の部分木を完了してから右の部分木へ進み，木全体を深さの降順で並べ替えない．条件付表現の依存を持たないグループは此の順で評価し，依存する判断の確定順は本書 3.4 に従う．

例の丸囲数字は此の評価順を示す説明用の番号であり，`NodeId`，演算子の結合順位又は原文のバイト位置ではない．同じ数字の境界は一緒に採否を決める．

## 3.2 文字数と測定区間

デコード・構文正規化済のトークンと，選択した表現が実際に生成する文字を測る．エスケープを出力へ残す場合は其の綴りの文字数を数える．Unicode のコードポイントを１文字とし，全角・半角の表示幅を区別しない．トークンの切出に用いる UTF-8 のバイト位置を文字数として扱わない．

| 対象 | 計数 |
|---|---|
| 通常のトークン，生成する行内空白，条件付記号，固定のトークン分離記法 | 数える． |
| 生成するインデント | 数えない． |
| コメント経路の通常コメント・ディレクティブコメント | 本文・記号・配置用空白を数えない． |
| ソースとして保持するリテラル・ドキュメント・埋込内容 | 各行の内容を数える．コメントに見えるテキストを機械的に除かない． |
| 改行 | 行の境界とし，幅には数えない． |
| 其の他の制御文字 | Unicode の一般カテゴリ `Cc` に属するコードポイントを数えない．非表示と云う理由だけで其の他のコードポイントを除外しない． |

此の除外は文字数の定義だけであり，制御文字の削除又は新規の記述を許す物ではない．結合文字・異体字セレクタ等を含め，`Cc` 以外の各コードポイントは１文字とする．

測定区間の両端では，折返に置換される生成済の区切空白だけを除く．リテラル・逐語領域の空白を一般の空白除去で削らない．通常の行内空白，型の接頭部，閉括弧の後へ続くトークン及び条件付で出す記号は数える．

通常のグループの評価では，区間の境界を次の通りに扱う．本書 3.4 で複数の判断を同時に決める単位の内側には，試す合法形の全選択を反映する．単位の外側の境界には次表を適用する．

| 境界 | 扱い |
|---|---|
| 必須改行，評価対象の始端・終端 | 常に残す． |
| 評価済で折返を残した他のグループ | 残す． |
| 未評価の他のグループ | 仮の境界として残す． |
| 評価済で折返を除いたグループ | 境界から除く． |
| 評価中のグループ | 読取上の仮の状態で全候補を除いて測る．インデックス其の物は変更しない． |

トークンの前で折る境界では当該トークンが右の区間へ，後で折る境界では左の区間へ入る．部分木自身の文字数だけでなく，此の区間へ一緒に入る呼出名・代入の接頭部・区切等を含める．

不変のトークンは幅の選択に必要な物だけを `LineBreaker` 内で１度計数し，改行の有無・先頭行幅・末尾行幅・最大行幅を要約として保持する．同じトークンを参照する平坦形・展開形・宣言の区分で計数を共有する．隣接する２つの要約と接続部を定数時間で合成し，複数の子を持つ並びは各接続部を１度だけ処理する．子孫を辿り直さない．必須境界が残る事又は他の制約だけで不採用と決まる候補は測らず，候補文字列を作って数え直さない．

候補の判定では，既存の区間要約と当該候補の記号・境界の差だけを読取専用で合成する．採用時だけ変更を纏めて反映し，棄却時の復元処理を設けない．区間端から除く生成済の区切空白を境界の左右で区別し，値に属する空白を削らない．

テキスト・境界位置が固定され，各物理境界が１つのグループ又は必須境界に対応し，残る操作が任意境界の除去だけである範囲では，平坦時の累積文字数と残存境界の双方向連結表を用いる．グループの境界を構文順に辿り，間に他の残存境界が在れば展開を保つ．全て連続する場合は，外側に残る左右の境界から累積値の差で幅を求め，上限内なら当該境界列を１度切り離す．本書 3.3 の採否・評価順を変えず，境界を除く度の幅の再集計を行わない．同じ位置の境界を複数のグループが共有する場合は，共有する保持条件を別に扱い，所属を１つへ潰して此の条件に適合させない．

条件付のトークン・境界が変わる範囲だけ，順序付の境界インデックスと区間要約の更新を用いる．固定範囲は前項の要約として共有し，候補差分の外は互いに重ならない既存の区間要約から合成する．採用差分の更新経路も纏め，同じ更新内の共通の要約を１度だけ更新する．確定済のトークンを再計数せず，毎回の全文・全グループ・全区間の集計を行わない．

累積値の差に使う文字数は正確に保持する．上限超過での計数打切は，残る寄与が非負で判定を覆さず，後の差分計算にも正確な値を要しない場合に限る．

## 3.3 通常のグループの評価

行幅が `0` の場合は，任意分割用の文字数計数・幅インデックス・候補の幅比較を行わず，合法な平坦形を選ぶ．子の必須展開又は意味上の境界が残るグループは対応する展開形を保つ．行幅が正でも，幅に依る選択を持たない領域に不要な幅インデックスを作らない．以下の上限比較は，行幅が正の場合に適用する．

候補を仮の境界とした状態から，本書 3.4 の順に各グループの全候補を一緒に除けるかを評価する．此の仮の配置は計算用の状態であり，不完全なソースを作って構文解析する手順ではない．

| 仮に全候補を除いた結果 | 決定 |
|---|---|
| 全候補が同じ測定区間へ収まり，幅が上限以下． | 当該グループの任意の折返を除く． |
| 同じ測定区間へ収まるが，幅が上限を超える． | 当該グループの折返を残す． |
| 他の残存境界を挟み，候補が複数の測定区間へ分かれる． | グループ全体を平坦化出来ない為，対応する展開形を残す． |

幅が上限と等しい場合は折らない．内側の展開が残ったコンテナでは，開き・内容・閉じの対応を保ち，入口と出口だけを勝手に平坦化しない．１つのグループの境界を別々に評価して一部だけ残す方式にも変えない．

例えば本書 5.2 の⑥は，未評価の⑯の `=` の後から，未評価の⑦の `[` の後迄を測る．⑥の採用後，⑦の区間は⑥の閉じの前から⑧のメンバ参照の前迄の `)[0]` に変わる．未評価の境界と採用済の境界の双方を使う為である．

文末其の物は終端境界として扱う．後続のコードが無い末尾セミコロンの後へ，不要な任意分割グループを設けない．

## 3.4 条件付表現の整合

`Group` の選択に依存する `IfBroken` は，当該グループの決定だけを参照する．別のグループの改行又は原文に在った改行で発火させない．子の必須展開を含む場合も，意味・構造の制約として対応するグループへ伝える．

グループの選択は，改行数の大域的な最小化を目的としない．グループと構造の対応を保ち，基準順位と本節の依存順に従って除ける折返だけを除く．

波括弧，Go のカンマ，分割宣言の型の接頭部，Python の継続括弧等は，評価する候補の幅と境界へ含める．記号を省いた幅でグループを確定してから，必要な記号を後付しない．劣後候補の要約を予め全て生成しない．

評価は中間表現内で完結させ，テキストの編集・再解析・アンカーの再束縛又は構文正規化への差戻を行わない．

### 評価の手順

グループには本書 3.1 の後行順で安定した順位を与える．同じ構文位置の複数グループには，`FormatIR` の子番号の列の辞書順に対応する順位を構築時の走査で付ける．深さに比例する経路列をグループ毎に複写して比較しない．原文の位置，`NodeId` の数値又は並列実行順を順位にしない．

条件付表現の採否が別のグループの測定区間に含まれる記号又は必須境界を変える場合は，其の表現を先に確定する．双方が互いの選択に依存する場合は，関係する判断だけを１つの決定単位へ纏め，本書 4.2, 4.3 の合法形と優先順位から同時に決める．決定単位の基準順位は含むグループの最小順位とし，元のグループの所属・識別子・採否を潰さない．依存と直接の決定手順は共通の生成形式に定義し，評価履歴の追跡・無効化・再登録で発見しない．通常のグループの未評価境界を仮に残して測る条件は本書 3.2 に従う．

決定単位の定義には，必要な要約，ローカル状態，条件分岐，優先順位，更新先及び処理量の上限を含める．同じ子の状態は共有し，ネスト・可変長の連鎖では次に必要な要約だけを合成する．単位を纏めた事だけを直接解決の根拠とせず，選択の全組合せ・全開始桁の表・候補毎の子部分木の再評価で代用しない．生成形式毎に要素当りの状態数・遷移数の上限を定義し，ネストでも状態の直積を作らず合成出来る事を検証する．最終出力の再整形に依る収束を用いない．

直接の依存と後続先は中間表現の構築時に対応付け，全グループの総当り比較又は間接依存の全列挙を行わない．依存の無い範囲では後行順を直接辿り，別の依存表・実行順表を作らない．依存する範囲だけ未確定の直接依存数と基準順位を用い，完了した直接依存を１度通知して次の単位を得る．未処理の全グループの再走査・整列，処理済の単位の再登録を行わない．

1. 宣言の区分は本書 4.1 に従って先に確定する．初期化子内の宣言も同じ要約と区分手順で扱う．通常のグループを処理した後に，空いた幅へ宣言子を詰め直さない．
2. 必須の表現と各決定単位の判定手順を用意する．同行形・見出の折返・本体のラッパーには本書 4.2 の優先順位を用い，後続の判断が使う共通要約だけを準備する．
3. 依存先が確定した決定単位を基準順位に従って１度だけ評価する．規定の優先順位で選択に必要な合法形だけを，対応する記号・境界を含む要約で測る．成立する最優先の形で当該単位のグループと `IfBroken` を同時に確定し，残る劣後候補は評価しない．候補文字列を組み立てない．
4. 採用時の判定結果を用い，確定した差分だけを本書 3.2 のインデックスへ反映する．結合後の測定区間の幅と必須条件は前項の判定で確認し，反映の為に同じ判定を行わない．後の単位では更新後の区間を用いる．条件付表現に依って確定済の条件を破る依存を残さず，確定済の判断の変更・棄却済の候補の再試行を行わない．
5. 全ての選択を確定し，実際の出力幅と必須条件を満たした時に終了する．未解決の依存は追加の巡へ回さない．分割不能な領域の超過と行幅 `0` は本書 1.2, 2.3 の扱いに従う．

予算の計数は整形仕様 9.2 に従う．本体のラッパー・末尾カンマ・継続括弧・値としての空白は，同じ評価処理で扱う．比較テストは本書 6.1 に従う．

### 完了条件

最終的な `BrokenIR` は次を満たす．

- `SoftBreak`，`IfBroken` 及びグループの選択を全て解決し，採用したトークンと改行を確定する．
- 分割可能な行は実際の出力文字数で上限を満たし，分割不能な領域では内容と意味を保持する．
- グループの選択，宣言子・式・文のアンカー及び検証用の構文対応を保持する．

不変条件の破壊は失敗，規定の探索予算を使い切った場合は見送とする．外部からの再整形で未解決の選択を隠さず，インデント・コメント配置・出力終端の工程で未解決の記号や改行を補わない．

# 第４章 構文別の選択条件

## 4.1 宣言の分割

分割対象は規約 6.2 と整形仕様 5.6 に従って統合済の宣言子のグループとする．一括宣言の成立条件は構文正規化で確認済とし，此処では行幅に依る出力区分だけを決める．宣言子毎の型が異なっても，同じグループの儘測定する．

行幅が `0` の場合は幅に依る宣言の分割を行わない．正の行幅では宣言子の順を維持し，各初期化子を幅非依存の平坦形で測って，同じ宣言として左から行幅内へ収まる最長の連続範囲を纏める．必須展開を持つ初期化子は其の構造を保ち，１行の宣言候補へ無理に押し込まない．次の宣言子を加えると上限を超える場合は，型・修飾等を備えた次の宣言を選ぶ．測定には各宣言で繰り返す共通の接頭部，各宣言子の型注釈及び終端記号を含める．１宣言子だけでも長い場合は，其の内部に許された通常の分割を用い，分割不能なトークンは保持する．

宣言子と共通接頭部の平坦要約を内側から１度構築し，左から加算して出力区分を確定する．初期化子内の関数・型・宣言も同じ要約を共有し，外側の区分判断の為に内部を走査し直さない．候補を１宣言子増やす度に既に測った本文を連結・計数し直さない．

此の選択を汎用のカンマ継続より先に確定し，別宣言にする規則と単なる要素の折返を混在させない．親が複数の宣言を許さない場合，リンケージ・属性・export 等を失う場合は，其の分割を選択肢にしない．アンカーは宣言子の識別子と出力上の対応で維持する．

## 4.2 制御本体と連鎖

幅非依存のラッパーは既に構文又は必須の表現として定まり，幅だけに依るラッパーを此処で選ぶ．

| 状況 | 選択 |
|---|---|
| 見出と単一文本体の同行形が規約上許され，上限内 | 同行形を保ち，任意のラッパーを出さない． |
| 見出に `{` を続けた形が上限内で，本体を別行へ送る必要が有る． | 必要な波括弧を出し，本体を次行へ置く． |
| 見出自体を折る必要が有る． | 行頭の閉括弧に続く `) Body;` を先に評価し，収まる場合は同行へ続ける． |
| `) Body;` も収まらない，又は本体の一般の式自体が複数行に為る． | 必要な波括弧と本体の展開形を選ぶ． |
| 中間のループ・条件の連鎖 | 最内の本体が複数行と云う理由だけで全段を包まない．連鎖の見出の折返と結合保持に必要な段だけを包む． |

`else` / `catch` / do-while の `while` は所属する本体の閉じへ続け，結合後の `} ` と後続を含めて測る．独立した `while` を同じ語と云う理由だけで結合しない．言語上省略出来ない波括弧を幅内と云う理由で除かない．

Kotlin の when の枝又はラムダの `->` の後に置く if 式では，後続の `else` が別の枝に為らない表現を選ぶ．連鎖全体で必要なラッパーの整合を取り，一部の枝のテキストだけを変更して読みを崩さない．

## 4.3 構文制約に依る表現

次表は入力側の解釈と中間表現の選択肢の対応であり，`LineBreaker` の言語別分岐ではない．全て同じグループ・必須境界・条件付断片で表す．

| 対象 | 選択に含める条件 |
|---|---|
| Go | 改行で自動セミコロンが挿入されるかを構文事実として扱う．必要な末尾カンマを含めて測り，メンバ参照の `.` は行末へ置く． |
| JSX / HTML | 属性間を候補とし，値・本文の意味を保てる閉境界だけを選ぶ．JSX の本文の空白が改行で失われる境界は選ばない． |
| Ruby | 単一文本体の分岐は `then` と本体を保って必要な節境界で折る．`case ... in` の必須改行と複数文本体は構造規則に従う．式本体の定義は定義形式を保って合法な式内の境界で折る（規約 5.3）．通常の波括弧に依るラッパーを代用しない． |
| Python | 本体は単一文でも次行へ展開する．括弧外の式の折返には合法な継続括弧を伴わせ，代入・反復・`del`・型注釈の構文単位を保つ． |
| CSS / SCSS | 要素区切・演算・条件の合法な境界を折る．識別子・数値と単位・URL・文字列本文を分断しない． |

JSX で単一の行内本文と属性を持つ要素では，属性だけを折って `>本文</Tag>` を同じ行へ続ける形と，子を展開する形を区別する．型引数を属性として数えず，本文・タブ・文字参照の意味を保持する．詳細な本文境界は整形仕様 6.6 に従う．

## 5.4 単一文本体のラッパー

