# Shave Format 行分割仕様

本書は `FormatIR` の折返候補の所属，評価順及び幅に依る選択を規定する．`LineBreaker` は原文又は解析木を書き換えず，宣言された選択肢を解決して `BrokenIR` を返す．実装の到達状況，補助関数名及び内部ファイル構成は規定しない．

整形全体の契約は [整形仕様](formatter_spec.md)，書式と表記は [コーディング規約](../CODING_STANDARDS.md) に従う．本書の節は「本書」，整形仕様の節は「整形仕様」，コーディング規約の節は「規約」として参照する．

# 第１章 適用範囲と責務

## 1.1 責務の分担

| 工程 | 本書に関係する責務 |
|---|---|
| `SourceProjector` | 文境界，密着，改行禁止及び逐語区画を構文事実へ変換する． |
| `SyntaxNormalizer` | 幅に依らない括弧・本体・宣言等を正規化する． |
| `Canonicalizer` | 構文上の役割から `SoftBreak`，`HardBreak`，`Group`，`IfBroken` 及び錨を生成する． |
| `LineBreaker` | 不変の `MaxChars` を唯一所有し，文字数を測って全ての選択を解決する． |
| `CodeLayout` | 解決済の範囲と改行へインデント・空行を具体化する．折返位置を選び直さない． |

境界と生成字句の差は `FormatIR` の値で表し，全言語に共通の選択手順を用いる．平坦時の空白は [字句間空白仕様](token_spacing_spec.md)，情報境界は整形仕様 3.5 に従う．

## 1.2 対象言語と適用範囲

全対象言語を同じ経路へ通し，意味を保って折れる境界を構文上の役割から生成する．HTML の属性間，CSS / SCSS の値の並び等も同じ判断に従い，言語全体を対象外にしない．Python の複合文本体は必須展開とし，単一文でも１行形を生成しない．行幅が `0` の場合も必須改行を消さず，幅だけを理由とする分割を省略する（整形仕様 2.1, 6.4）．

# 第２章 候補と群の構成

## 2.1 構文上の所属

分割候補は字句其の物ではなく，構文の役割が定める境界である．解析器が字句を名前付又は無名の何方として出すかを，候補の可否又は優先順位の根拠にしない．

`SoftBreak` には平坦時の表現と折返時の表現を定める．前者は密着又は必要な空白，後者は合法な改行とする．文を終える必須改行及び標準構文の必須境界は，任意の候補でなく `HardBreak` 又は対応する制約で表す．コメント経路の指示子の適用条件から，分割候補・群・必須境界を追加しない（整形仕様 4.5）．

同じ構文単位で一緒に採否を決める境界を，一つの `Group` に所属させる．例えば実引数の並びの開きの後，要素を区切るカンマの後及び閉じの前は同じ群とする．各要素の内側の呼出・式・配列は別の子の群を持つ．

次の所属を明示する．

| 構文 | 群の構成 |
|---|---|
| 実引数・仮引数・配列・オブジェクト等 | 開き・区切り・閉じを対応付ける．空の並びの内部には任意の候補を作らない． |
| 二項式・三項式・代入式 | 当該の演算を構成する境界を同じ群にする．別の部分式の演算子と混同しない． |
| 初期化文を持つ見出 | 初期化・条件・更新を区切るセミコロンを見出の群へ所属させる．初期化文の終端という解析器側の親子関係を引き継がない． |
| メンバ参照・後置連鎖 | 呼出の実引数の群と，受け手から続く参照の群を区別する． |
| 分割可能な文字列の並び | 言語が別の字句として並べれる要素の境界を候補にする．リテラル本文の内部は対象にしない． |
| 単一文の制御本体 | 同行の本体と，必要時の包装・改行を同じ意味の選択肢として表す． |
| JSX / HTML の属性 | 属性間と合法な閉じ境界に候補を置く．属性値・本文の内部と区別する． |
| CSS / SCSS の要素・演算 | カンマで区切る並び，合法な演算及び条件の境界を群にする．選択子又は値に新しい意味上の空白を作らない． |

隣接文字列の境界は，先頭の子より後を対象とする．Ruby の `%w` / `%i` の様に要素の並びとして扱う物では先頭要素の前も候補に出来るが，開始記号・内容・終端の意味を保持する．Ruby の隣接文字列連結は，本書 2.3 の分割禁止を優先する．

`NodeId` と錨は群の平坦形・展開形の何方にも対応付ける．群を選んだ後に原文の位置又は再解析で所属を探し直さない（整形仕様 3.2, 6.1）．

## 2.2 折返の側

折る場合に字句を前行へ残すか次行へ送るかは，`Canonicalizer` が構文上の役割と共に表す．行幅を測ってから字句の役割を推測しない．

| 役割 | 折返位置 | 代表例 |
|---|---|---|
| 開きの区切り | 後 | `(`, `[`, `{` |
| 要素・見出の区切り | 後 | `,`, `;` |
| 二項・三項・代入・アロー | 後 | `+`，`&&`，`=`，`?`，`:`，`=>`，語の演算子 |
| 閉じの区切り | 前 | `)`, `]`, `}` |
| メンバ参照・スコープ | 原則として前 | `.`, `?.`, `->`, `::` 等，参照を表す物 |
| Go のメンバ参照 | 後 | `.` |
| Go の節見出 | 前又は必須境界 | `case`, `default` |
| Ruby の節の境界 | 前 | `elsif`, `when`, `else`, `rescue`, `ensure`, `end` 等 |

此の表は字面の一括分類ではない．前置の `-`，型の `*`，捕捉の `&`，閉じを持たない範囲等を，二項演算子又は通常の区切りとして折らない．先頭の `const` / `new` 等も，語である事だけを理由に候補にしない．

複数行の行頭へ置いた閉じ括弧の後は，次も閉じ括弧なら次行へ送り，其れ以外は同じ行へ続ける．`},`，`};`，`} else`，`} catch`，do-while の `} while`，宣言名，`from`，代入，型表明及び後置連鎖も含め，接続後の幅で判断する（規約 2.5，整形仕様 6.3）．

## 2.3 候補にしない境界

意味を保つ合法な分割だけを候補にする．分割不能な区画が行幅を超えても，其れだけを理由にファイル全体を見送らない．

| 対象 | 分割を抑止する範囲又は条件 |
|---|---|
| 逐語区画 | リテラル本文，マクロの字句列，地の文，データ，許容した誤り区画等の内部． |
| 空の括弧 | `()` / `[]` / `{}` の内側．空行を作っても幅を減らせない． |
| 単項演算・型の接尾記号 | 被演算子・型との密着を壊す位置．Swift の後置 `?` / `!` 等を含む． |
| 仮引数の囲み | Rust / Ruby の `\|` の直後を通常の二項演算子の候補にしない．内部のカンマ等は別に扱う． |
| 前処理指令 | 連結した C / C++ の指令，C# の `#pragma` 等の１論理行の内部． |
| 型注釈と初期化子を持つ宣言 | Rust の束縛，Kotlin の戻値型と式本体等で，型の `:` を初期化の `=` と一律に同じ分割群へ入れない． |
| C++ のラムダ捕捉 | 捕捉の `&` / `=` / `*` を名前等から切り離す位置． |
| Java / Swift の import | 完全修飾名の内部． |
| Swift の見出の束縛 | 条件内の `=` の直後を，条件の区切りのカンマと同じ群にしない． |
| PHP のキャスト・地の文 | キャストの不可分範囲と，出力本文を変更するタグ境界． |
| JSX の本文 | 対象処理系で同じ内容を保持出来ない行端と，属性の無いタグの内部． |
| TypeScript の省略可能な名前 | `name?: T` の `?` と型注釈を分断する位置． |
| TypeScript の比較と型引数 | `a < b >` の後等，改行で別の文又は型引数の読みへ変わる位置． |
| Ruby のヒアドキュメント | 開始字句を含む論理行の全体．開始行の途中の折返でも本文の起点が変わる． |
| Ruby の修飾子 rescue | 改行で独立した rescue 節へ変わる内部境界． |
| Ruby の隣接文字列連結 | 別の文又は別の値として読まれる境界． |

解析器が演算子を節点の末尾へ取り込んだ等の誤読は，入力適応と投影で解決する．中核へ誤読を残して「元の字面を見れば折れる」候補を作らない（整形仕様 4.2, 4.3）．

# 第３章 選択の確定順

## 3.1 全体の順序

１回の `Resolve` は次の順で行う（整形仕様 6.4）．

1. 構文・構造・逐語内容に関する必須条件を満たす選択肢だけを残す．
2. 分割可能な統合宣言の群を確定する．
3. 通常の分割群を，本書 3.3 の順に評価する．
4. 条件付の波括弧・継続括弧・末尾カンマ・空白の値表現を含め，本書 3.4 に従って選択を整合させる．

群は構文の並びを左から右へ辿り，子の群を処理してから親の群を処理する**後行順**とする．左の部分木を完了してから右の部分木へ進む．木全体を深さの降順で並べ替える方式ではない．

例の丸囲み数字は此の評価順を示す説明用の番号であり，`NodeId`，演算子の結合順位又は原文のバイト位置ではない．同じ数字の境界は一緒に採否を決める．実装の並列実行順で番号又は結果を変えない．

## 3.2 文字数と測定区間

復号・構文正規化済の字句と，選択した表現が実際に生成する文字を測る．解析用の退避を戻す復号と，出力へ残すエスケープを値へ展開する処理を混同しない．エスケープを出力へ残す場合は其の綴りの文字数を数える．Unicode の符号位置を１文字とし，全角・半角の表示幅を区別しない．字句の切出に用いる UTF-8 のバイト位置を文字数として扱わない．

| 対象 | 計数 |
|---|---|
| 通常の字句，生成する行内空白，条件付記号，固定の字句分離記法 | 数える． |
| 生成するインデント | 数えない． |
| コメント経路の通常コメント・指示コメント | 本文・記号・配置用空白を数えない． |
| ソースとして保持するリテラル・文書・埋込内容 | 各行の内容を数える．コメントに見える字面を機械的に除かない． |
| 改行 | 行の境界とし，幅には数えない． |
| 其の他の制御文字 | Unicode の一般カテゴリ `Cc` に属する符号位置を数えない．非表示という理由だけで其の他の符号位置を除外しない． |

此の除外は文字数の定義だけであり，制御文字の削除又は新規の記述を許す物ではない．結合文字・異体字選択子等を含め，`Cc` 以外の各符号位置は１文字とする．

測定区間の両端では，折返に置換される生成済の区切空白だけを除く．リテラル・逐語区画の空白を一般の空白除去で削らない．通常の行内空白，型の接頭部，閉じ括弧の後へ続く字句及び条件付で出す記号は数える．

通常の群の評価では，次を区間の境界として扱う．

| 境界 | 扱い |
|---|---|
| 必須改行，評価対象の始端・終端 | 常に残す． |
| 評価済で折返を残した他の群 | 残す． |
| 未評価の他の群 | 仮の境界として残す． |
| 評価済で折返を除いた群 | 境界から除く． |
| 評価中の群 | 全ての候補を一時的に除いて測る． |

字句の前で折る境界では当該字句が右の区間へ，後で折る境界では左の区間へ入る．部分木自身の文字数だけでなく，此の区間へ一緒に入る呼出名・代入の接頭部・区切り等を含める．

不変の字句の計数は `LineBreaker` 内で一度行い，改行の有無・先頭行幅・末尾行幅・最大行幅を要約として保持する．断片を連結する時は，左右の要約と，左の末尾行幅に右の先頭行幅を加えた値から新しい要約を求める．候補文字列を作って数え直さない．

区間の幅と前後の残存境界は索引で求める．選択変更では影響する断片と区間だけを更新し，変更していない字句を再計数しない．区間端の区切空白を除く条件も断片の種別で保持し，値に属する空白を削る集計へ置き換えない．

## 3.3 通常の群の評価

行幅が `0` の場合は幅の比較を行わず，合法な平坦形を選ぶ．子の必須展開又は意味上の境界が残る群は対応する展開形を保つ．以下の上限比較は，行幅が正の場合に適用する．

候補を仮の境界とした状態から，後行順に各群の全候補を一緒に除けるかを評価する．此の仮の配置は計算用の状態であり，不完全なソースを作って構文解析する手順ではない．

| 仮に全候補を除いた結果 | 決定 |
|---|---|
| 全候補が同じ測定区間へ収まり，幅が上限以下． | 当該群の任意の折返を除く． |
| 同じ測定区間へ収まるが，幅が上限を超える． | 当該群の折返を残す． |
| 他の残存境界を挟み，候補が複数の測定区間へ分かれる． | 群全体を平坦化出来ない為，対応する展開形を残す． |

幅が上限と等しい場合は折らない．内側の展開が残った容器では，開き・内容・閉じの対応を保ち，入口と出口だけを勝手に平坦化しない．一つの群の境界を別々に評価して一部だけ残す方式にも変えない．

例えば本書 5.2 の⑥は，未評価の⑯の `=` の後から，未評価の⑦の `[` の後迄を測る．⑥の採用後，⑦の区間は⑥の閉じの前から⑧のメンバ参照の前迄の `)[0]` に変わる．未評価の境界と採用済の境界の双方を使う為である．

文末其の物は終端境界として扱う．後続のコードが無い末尾セミコロンの後へ，不要な任意分割群を設けない．

## 3.4 条件付表現の整合

`Group` の選択に依存する `IfBroken` は，当該群の決定だけを参照する．別の群の改行又は原文に在った改行で発火させない．子の必須展開を含む場合も，意味・構造の制約として対応する群へ伝える．

本書 3.3 の後行順に依る群の選択は，改行数の大域的な最小化を目的としない．群と構造の対応を保ち，規定した順で除ける折返だけを除く．

波括弧，Go のカンマ，JSX の空白の式，分割宣言の型の接頭部，Python の継続括弧等は，選択した時点で幅へ含める．選択に因って隣の測定区間又は条件が変わった場合は，次の基準手順で再評価する．

再評価は中間表現内で完結させ，字面の編集・再解析・錨の再束縛又は構文正規化への差戻を行わない．

### 再評価の基準手順

群には構文上の左から右への後行順で安定した番号を割り当てる．同じ構文位置の複数群は，`FormatIR` 内での子番号の列を辞書順に比較して順序を定める．原文の位置，`NodeId` の数値又は並列実行順を順位にしない．

1. 宣言の区分は本書 4.1 に従って先に確定する．通常の群を処理した後に，空いた幅へ宣言子を詰め直さない．
2. 必須の表現を選び，任意の制御本体は合法な同行形を初期形とする．複数の合法形が在る場合は，本書 4.2 の優先順位で選ぶ．
3. 此の巡の条件付表現を固定し，通常の群を全て未評価の状態から後行順で評価する．各群を平坦化する試行では，当該群に従う `IfBroken` も同時に平坦形へ切り替えて測る．他の群に従う断片は此の巡の状態を用いる．
4. 同じ後行順で制御本体・条件付断片を評価し，必要な表現変更を直ちに反映する．後の評価は其の変更を見た状態で行う．記号・分割境界又は測定区間が変わった場合は，次の巡で通常の群を初めから評価する．
5. 全ての群・条件付断片・宣言区分が１巡前と一致し，実際の出力幅と必須条件を満たした時に終了する．分割不能な区画の超過と行幅 `0` は本書 1.2, 2.3 の扱いに従う．直前との一致は収束であり，変更を挟んで以前の完全な状態へ戻る場合は循環として失敗する．

再評価の状態は，群の選択，条件付断片の採否，宣言区分及び必須境界を含む．部分集合又はハッシュ値の一致だけで収束又は循環と判断しない．予算と再利用の計数は整形仕様 9.2 に従う．

### 依存関係に依る評価の再利用

各評価は，参照した群の選択，条件付断片，幅の要約，左右の残存境界及び測定区間を記録する．変更が在った値に依存する評価だけを無効にし，基準手順の順序で作業列へ戻す．部分木の幅だけをキーにせず，先行群の選択が変えた区間と未評価の仮境界も依存先へ含める．

各巡の「全て未評価」は選択上の状態であり，実装上の記録の全削除を要求しない．前提と基準順での先行処理の効果が同じ範囲は，評価結果と境界更新を再利用する．依存先の変化を見落とす順不同の局所貪欲法や，一度折った群を常に折った儘とする方法へ変更しない．

本体の包装・末尾カンマ・継続括弧・値としての空白は，同じ再評価器で扱う．比較試験は本書 6.1 に従う．

### 完了条件

最終的な `BrokenIR` は次を満たす．

- `SoftBreak`，`IfBroken` 及び群の選択を全て解決し，採用した字句と改行を確定する．
- 分割可能な行は実際の出力文字数で上限を満たし，分割不能な区画では内容と意味を保持する．
- 群の選択，宣言子・式・文の錨及び検証用の構文対応を保持する．

循環又は不変条件の破壊は失敗，循環を検出せずに規定の探索予算を使い切った場合は見送とする．外部からの再整形で非収束を隠さず，インデント・コメント配置・出力終端の工程で未解決の記号や改行を補わない．

# 第４章 構文別の選択条件

## 4.1 宣言の分割

分割対象は規約 5.3 と整形仕様 5.6 に従って統合済の宣言子の群とする．一括宣言の成立条件は構文正規化で確認済とし，此処では行幅に依る出力区分だけを決める．宣言子毎の型が異なっても，同じ群の儘測定する．

行幅が `0` の場合は幅に依る宣言の分割を行わない．正の行幅では宣言子の順を維持し，各初期化子を幅非依存の平坦形で測って，同じ宣言として左から行幅内へ収まる最長の連続範囲を纏める．必須展開を持つ初期化子は其の構造を保ち，１行の宣言候補へ無理に押し込まない．次の宣言子を加えると上限を超える場合は，型・修飾等を備えた次の宣言を選ぶ．測定には各宣言で繰り返す共通の接頭部，各宣言子の型注釈及び終端記号を含める．１宣言子だけでも長い場合は，其の内部に許された通常の分割を用い，分割不能な字句は保持する．

宣言子と共通接頭部の幅の要約を使い，左から加算して出力区分を確定する．候補を１宣言子増やす度に既に測った本文を連結・計数し直さない．

此の選択を汎用のカンマ継続より先に確定し，別宣言にする規則と単なる要素の折返を混在させない．親が複数の宣言を許さない場合，リンケージ・属性・export 等を失う場合は，其の分割を選択肢にしない．錨は宣言子の識別子と出力上の対応で維持する．

## 4.2 制御本体と連鎖

波括弧の要否を元の本体の字面から判断しない．幅非依存の包装は既に構文又は必須の表現として定まり，幅だけに依る包装を此処で選ぶ．

| 状況 | 選択 |
|---|---|
| 見出と単一文本体が合法な同行形で上限内 | 同行形を保ち，任意の包装を出さない． |
| 見出に `{` を続けた形が上限内で，本体を別行へ送る必要が有る． | 必要な波括弧を出し，本体を次行へ置く． |
| 見出自体を折る必要が有る． | 行頭の閉じ括弧に続く `) Body;` を先に評価し，収まる場合は同行へ続ける． |
| `) Body;` も収まらない，又は本体の一般の式自体が複数行に為る． | 必要な波括弧と本体の展開形を選ぶ． |
| 中間のループ・条件の連鎖 | 最内の本体が複数行という理由だけで全段を包まない．連鎖の見出の折返と結合保持に必要な段だけを包む． |

`else` / `catch` / do-while の `while` は所属する本体の閉じへ続け，結合後の `} ` と後続を含めて測る．独立した `while` を同じ語という理由だけで結合しない．言語上省略出来ない波括弧を幅内という理由で除かない．

Kotlin の when の枝又はラムダの `->` の後に置く if 式は，後続の `else` が別の枝に為らない表現を選ぶ．連鎖全体で必要な包装の整合を取り，一部の枝の字面だけを変更して読みを崩さない．

## 4.3 構文制約に依る表現

次表は入力側の解釈と中間表現の選択肢の対応であり，`LineBreaker` の言語別分岐ではない．全て同じ群・必須境界・条件付断片で表す．

| 対象 | 選択に含める条件 |
|---|---|
| Go | 改行で自動セミコロンが挿入されるかを構文事実として扱う．必要な末尾カンマを含めて測り，メンバ参照の `.` は行末へ置く． |
| JSX / HTML | 属性間を候補とし，値・本文の意味を保てる閉じ境界だけを選ぶ．JSX の必要な空白の式も幅へ含める． |
| Ruby | 単一文本体の分岐は `then` と本体を保って必要な節境界で折る．`case ... in` の必須改行と複数文本体は構造規則に従う．式本体の定義は定義形式を保って合法な式内の境界で折る（規約 6.12）．通常の波括弧に依る包装を代用しない． |
| Python | 本体は単一文でも次行へ展開する．括弧外の式の折返には合法な継続括弧を伴わせ，代入・反復・`del`・型注釈の構文単位を保つ． |
| CSS / SCSS | 要素区切・演算・条件の合法な境界を折る．識別子・数値と単位・URL・文字列本文を分断しない． |

JSX で単一の行内本文と属性を持つ要素は，属性だけを折って `>本文</Tag>` を同じ行へ続ける形と，子を展開する形を区別する．型引数を属性として数えず，本文・タブ・文字参照の意味を保持する．詳細な本文境界は整形仕様 6.6 に従う．

## 5.4 単一文本体の包装

```typescript
for(let i = 0; i < imageData.data.length; i += 4) if(imageData.data[i + 3] < alpha) imageData.data.set([0XFF, 0XFF, 0XFF, 0X1], i);
```

数値の大文字化は構文正規化で完了している．波括弧は原文へ仮挿入せず，二つの制御本体の条件付表現として評価する．`for` の二つのセミコロンは見出の同じ群に所属する．

| 評価対象 | 文字数 | 決定 |
|---|---|---|
| `imageData.data.set([0XFF, 0XFF, 0XFF, 0X1], i);` | ４７ | 呼出本体は１行に保つ． |
| `if(imageData.data[i + 3] < alpha) imageData.data.set([0XFF, 0XFF, 0XFF, 0X1], i);` | ８１ | `if` の同行形は収まらない． |
| `if(imageData.data[i + 3] < alpha) {` | ３５ | 条件は折らず，本体を包装して次行へ置く． |
| `for(let i = 0; i < imageData.data.length; i += 4) if(imageData.data[i + 3] < alpha) {` | ８５ | 中間の `for` から `if` 迄の連鎖も収まらない． |
| `for(let i = 0; i < imageData.data.length; i += 4) {` | ５１ | `for` の見出を保ち，其の本体も包装する． |

```typescript
for(let i = 0; i < imageData.data.length; i += 4) {
	if(imageData.data[i + 3] < alpha) {
		imageData.data.set([0XFF, 0XFF, 0XFF, 0X1], i);
	}
}
```

外側の包装は，内側が複数行という理由だけで付いた物ではない．連鎖した見出の８５文字が上限を超える為に必要である．より広い行幅で連鎖が収まる場合は，本書 4.2 の中間本体の規則に従う．

# 第６章 受入条件

## 6.1 合格条件

整形仕様第１１章の試験に加え，本書の判断を次の単位で確かめる．試験器の存在だけを合格の根拠にしない．

| 項目 | 合格条件 |
|---|---|
| 後行順 | 子を先に，親を後にし，左の部分木を完了してから右へ進む． |
| 群の採否 | 同じ群の候補を一括で評価する．開きと閉じの一方だけを取り残さない． |
| 測定区間 | 未評価・採用済の境界を残し，除去済の境界を使わない． |
| 幅の境界 | 上限の直前・一致では不要な分割をせず，直後では合法な分割を選ぶ． |
| 宣言の分割 | 統合済の群を宣言子順と実際の出力幅で区分する．共通の接頭部と各宣言子の型注釈を数え，型の違い・用途・使用箇所・コメントだけで分割しない． |
| 条件付の記号 | 波括弧・カンマ・継続括弧・宣言の接頭部・JSX の空白の式を計数から落とさない． |
| 制御本体 | 同行形，見出だけの折返，`) Body;`，本体の展開及び中間の連鎖を区別する． |
| 文字数 | 非 ASCII の字句を符号位置で測り，バイト数・表示桁・インデントを混入させない． |
| 分割不能 | リテラル・逐語区画・ヒアドキュメント開始行を壊さない． |
| 無制限 | 幅が `0` でも必須改行・包装・境界を保持する． |
| 決定性 | 同じ中間表現と行幅から同じ `BrokenIR` を返す．並列実行順を結果へ反映しない． |
| 情報境界 | 投影後のソース構文が同じなら，原文の非意味的空白と指示コメントを含むコメントの変異で，群・採否・コード出力・空行が変わらない． |
| 共通の適用 | 同じ役割の属性・値・宣言を言語名又は元の記法で除外しない．Python の本体は幅に依らず展開する． |
| 再評価 | 初期状態・群の後行順・条件付記号の即時反映・再走査範囲・固定点が本書 3.4 と一致する． |
| 完結と冪等性 | 未解決の選択を後段へ渡さず，同じ設定の再整形で結果を変えない． |
| 失敗分類 | 循環，予算超過及び検証失敗を整形仕様 8.3, 9.2 と同じ分類にする． |

比較試験は整形仕様 11.1 に従い，本書 3.4 の基準手順と照合する．検体にはネスト，相互依存する包装，幅が非単調に変わる選択，左右の区間変更，上限の直前・一致・直後及び `0` を含める．字句の再走査と候補文字列の複写は区別して計数する．

## 6.2 検体の保守

本書の例は仕様上の期待結果であり，整形器本体の実行済記録ではない．規則を変更する場合は，例の区間・文字数・採否・出力を一緒に更新する．
