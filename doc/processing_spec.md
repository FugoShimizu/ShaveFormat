# Shave Format 整形仕様

本書は，`Formatter::Format` から呼び出す Shave Format の整形工程を規定する．

---

## 1. 整形の絶対原則

整形結果は以下の原則を全言語横断で**例外無く**満たさなければならない．是等は性能・利便性に優先する．

### 1.1 元ソース非依存

> 同じ意味のコードに対する整形出力は，元ソースの改行・インデント・空行の有無や位置に**依らず**，必ず１つの形に一意に定まる．原文が構文エラーの場合を除き，原文返戻は一切行わない．

整形出力は AST 構造のみから決定し，元ソースの改行・空白・空行を**整形結果に残さない**．

- 改行を跨ぐ式 `(a +\n b)` と１行の式 `(a + b)` は同一出力．
- 空行が `if` と `else` の間に有っても無くても，`} else` 結合結果は同一．
- インデントの種類（タブ／２スペース／４スペース）に関係なく，`FinalizeLayout` がタブで再計算した同一深さで出力する．

Python の構文上のインデント，ヒアドキュメント本文，Kotlin の型位置の注釈と `(` の間の空白 (`@Composable () -> Unit`) 等はレイアウトでなく構文又は内容であり，意味を保つ為に維持する．整形困難や構文破壊の虞は原文返戻の理由にせず，意味を変えない一意の形へ整形する．

- 原文返戻を許すのは，構文解析器が入力に構文エラー（許容対象外の `ERROR` / `MISSING`）を検出した場合に限る．此の場合は改行様式と末尾改行も入力時の形を保持する．
- 整形後の構文検査（§ 3.11）は，本原則を破る不具合を利用者へ届けない為の最終防壁である．発火は不具合として扱い，発火させた整形を直す．
- 対応外の言語（拡張子・言語識別子が未対応）と符号化（BOM で判る UTF-16 / UTF-32）は整形の対象外で，原文返戻には当たらない．入力と出力の大きさの上限（§ 3.1，§ 4.1），構文解析器が要素の名前を追えない HTML のネストの深さ（§ 4.1）と，記憶域・走脈を使い切った実行も同じく整形の判断ではなく実行環境の限界である．

### 1.2 コメント非依存

> コメントの有無・位置に依って**コメント以外の部分**の整形結果が変動してはならない．

コメント自身の移動・脱落は許容するが，行内コメントは § 1.7 に従い，コメントを整形判断に使わない．`AttachComments` がコメントを除去して AST ノード ID へ紐付け，整形後に `FinalizeLayout` が再挿入する．コメント自身を処理する工程だけを除去前に実行する．HTML コメントは文書の節点の為に除去せず，子の境界判定では描画されない子として飛ばす（§ 3.3，§ 3.5.1）．

`AttachComments` はコメントが未だソースに在る段階で紐付先を決める為，紐付先を決める判定は**ソースの字面ではなく AST の節点種別**で行う．字面ではコメント本文の末尾を閉じ字句と読み違え（`# end` を Ruby の `end` と看做す等），コメントの中身が判断の材料に化ける．

- 例：`if (x) {\n // cmt\n stmt\n}` と `if (x) {\n stmt\n}` は，コメント除去後で同じ整形結果に為る事．
- コメントのアンカーが見付からない場合（コメントのみのファイル／空ブロック内コメント等）は最終退避経路としてルートに `Trailing` 紐付して整形結果に残す．ソース残置は行わない．
- PHP の地の文（出力其の物）に差込先が当たるコメントは，本文が出力へ混入する為，錨の後の同じ行の閉じタグの直前（PHP の側）へ移す（`<?= 'a'; /* c */ ?>`．行コメントも `?>` で終わる為に同じ：`<?= 'a'; // c ?>`．末尾コメントは同じ行の最後の閉じタグの直前）．地の文で始まる行（`?>` の後の地の文に続く `<?php echo $x; ?>`．行を逐語で写す）のコメントも，同じ行の閉じタグの直前へ移して逐語の行へ差し込む（行の前へ回した行内の行コメントは，行頭が錨の位置でない為に行の最初の閉じタグの直前：`<li><?php /* c */ echo $x; ?>` → `<li><?php echo $x; /* c */ ?>`）．同じ行に閉じタグの無いコメントは落とす．ファイルの先頭の行頭（最初の開始タグの前：`<?php // c ?>` の空の区画のコメント）と，閉じ括弧で始まる行の行末（行内の行コメントの置く先）も差込先に含めて判定する．
- 行コメントは行を占める記法で行の途中に置けない為，錨が行の途中へ移った場合は行頭へ回す．ブロックコメントは錨の直前へ行内で差し込む (`} else /* c */ n = 2;`)．
- 検査工程が機械的に確かめる：環境変数 `SHAVEFMT_DROP_COMMENTS` を立てるとコメントを書き戻さない．`tools/golden_test.sh` は，此の設定で元入力を整形した結果を，同じ設定で再整形した結果と比較する．更に，通常設定で整形した結果を此の設定へ通し，元入力から直接得たコメント無の結果と比較する．検体毎に冪等性と通常経路のコメント非依存を検査する物で，全入力に対する証明ではない．

### 1.3 冪等性

> 整形結果に再度同じ整形を適用しても結果が変化しない．

`Format(Format(x)) == Format(x)` を，部分整形を含む全言語で保証する．`LineSplit` / `VarDeclMerge` 等の反復処理も固定点で停止する．

### 1.4 簡潔性＞可読性

整形ルールは可能な限り１行に収める方向に倒す．冗長なブレース・空行・冗長括弧は積極的に除去する．此れは [`CODING_STANDARDS.md`](../CODING_STANDARDS.md) の規約 1.3「簡潔性＞可読性」と一致する．

### 1.5 展開した閉じ括弧の後続 (MUST)

> 複数行に展開した行頭の閉じ括弧（`)` `]` `}`）の後に続く閉じ括弧は次行へ置き，其れ以外の字句は同一行に続ける．

複数行に展開したブロック・引数列・配列等の閉じ括弧は行頭に置き，構文・式の結合を変えない．

- 次行へ置く：`}` の後の `)` / `]` / `}`，`)` の後の `)` 等
- 同一行に続ける：`},` / `};` / `} else` / `} while(...);` / `} catch(...)` / `} Name;` / `} from "./module";` / `} = Source;` / `} as const;` / `} || Fallback;` / `} {`（戻り値の型注釈に続く本体）/ `}.Member` / `).then(Handler)` / `].map(Transform)` / `}[Key]` / `}()`

```cpp
// ❌ `}` と `)` が同一行
std::sort(arr.begin(), arr.end(), [](int a, int b) {
	return a < b;
});

// ✅ `)` と `;` は次行
std::sort(
	arr.begin(),
	arr.end(),
	[](int a, int b) {
		return a < b;
	}
);
```

`StructurePass::ShouldBreakAfterExpandedBrace` と行分割工程は，次行へ送る閉じ括弧を判定する．Go は自動セミコロン挿入を避ける為に対象外とし，行分割が末尾コンマを補う場合だけ閉じ括弧を次行へ置く．Ruby・Go で式の結合が変わる場合は § 3.11 の最終防壁で差し戻し，不具合として扱う．

### 1.6 インデント深度の遷移境界 (MUST)

> インデント深度は構文上のブロック・行を跨ぐ括弧対の境界で変化し，途中で任意に増減しない．アクセス修飾子の節・ラベルは当該行のみ１段浅く配置する．

括弧対は開始行の次行から１段深くし，閉じ括弧行は開始側の深さへ戻す．Python の本体は構文上のインデント境界に従う．

- ✅ `{` 開いた次行から内容は +1 深い
- ✅ `}` 閉じる行は親と同じ深さ（内容より −1）
- ❌ 引数リストの途中で含意的な深度変化（`(` の中で２段深くする等）は禁止．

#### 例外：アクセス修飾子の節・ラベル

以下のセクションヘッダ系は当該行のみ内容より１段浅く配置する（直後の内容は通常の深さに戻る）：

- C++ アクセス修飾子：`public:` / `private:` / `protected:`
- `case` / `default` ラベル（C / C++ / C# / Java / Go / JS / TS の switch）
- `goto` ラベル (`label:`)
- ループラベル（`outer: for(...)` 等）

```cpp
// ✅
class Foo {
public: // ← １段浅

	void Bar() { // ← 元の深さ
		switch(x) {
		case 1: // ← １段浅
			DoA(); // ← 元の深さ
			break;
		}
	}
};
```

Python の `case` は構文本体としてインデントする．Ruby の `when` / `in` / `rescue` / `else` / `ensure` / `elsif` も同様にセクションヘッダとして１段浅く扱う（AST 深さベース計算で −1）．

本規則の機械的保証：

- ブラケットペアベース言語：各行のインデント＝「先頭バイトより前に開きで先頭バイトより後で閉じる行跨ぎペアのうち起点行が異なる物の数」．同じ行で開く括弧は，其の行で先に閉じた括弧の起点を引き継ぎ（`} else {`），無ければ其の行で先に開いた括弧と起点を共有する（`}(struct {` の中身を二段下げない）．行頭が行跨ぎ閉じ括弧／セクションヘッダの場合 −1．
- AST 深さベース言語 (Ruby / Python)：`IndentBlock` / `RubyBlock` / `JsxElement` で +1，セクションヘッダで −1．

### 1.7 行内コメントの保持 (MUST)

> 原文でコードの後に置いたコメント（行内・行末のコメント）は，整形後も行内のコメントの儘，説明対象の構文が在る行の末尾に置く．コメントの順と形式（行コメント・囲みコメント）も変えない．

- ✅ 宣言の統合・波括弧の除去等で同じ行に並んだ行内のコメントは，原文の順で其の行の末尾へ連ねる（`const int A = 1, B = 2; // first // second`，`if(a == 1) g(); // 理由 // 終端コメント`）．
- ❌ 行内のコメントを行の前・後の独立した行へ移す事，並びの順を入れ替える事，行コメントを囲みコメントへ書き換える事（`// a` → `/* a */`）．
- ✅ 見出しの字句の直後の行末コメント（`try { // c` / `} else { // c` / `default: // c` / Ruby の `else # c` / Python の `finally:  # c`）は，本体の最初の要素の先行コメントとして見出しの行の行末に置く（波括弧の除去・付与や節の畳込の後も同じ行：`else h(); // c`）．波括弧を直に持つ構文（Swift / Kotlin）の閉じ波括弧の直後の行末コメントは，閉じ波括弧の行へ連なる次の節の見出しの行の行末に置く（`} catch { // c`）．
- ✅ 原文で独立した行に在ったコメントの錨が行の途中へ移る時（宣言の統合・畳んだ仮引数や型の要素の並び・波括弧を外した本体），囲みコメントは錨の直前の行内へ置き（文書化コメント `/** 幅 */ w: number`・束ね器の注釈 `/*#__PURE__*/` が紐付く構文を変えない為），行コメントは錨の行の前（閉じ括弧で始まる行と Ruby の畳んだ節の行では行末）へ置く（§ 1.2）．直後の兄弟との間に名前の無い字句（`.` / `->` / `?.` / `[` / 二項演算子等）が在ったコメントは，錨が行の途中なら其の字句の前へ置き順を保つ（`foo()` と `.baz()` の間の `/* z */` → `foo() /* z */ .baz()`・`a /* c */ + b`．`CommentAttach::IsBeforeToken`）．行内へ置いた囲みコメントの後の同じ錨の行コメントは，行の前へ置くと順が入れ替わる為に錨の行の行末へ置き，其の後のコメントも続けて置く（`/* block */` と `// line` の次の行の `.foo()` → `a /* block */ .foo() // line`．次の行に作用する指令は作用する行を変えない為に行の前）．閉じ波括弧と後の節（`} // c` の次の行の `else {` / `catch(e) {`）の間の独立した行のコメントは，節が閉じ波括弧の行へ連なる為，節の本体の最初の文の前へ置いて順を保つ（`} else { // c` の次の行）．
- 行コメントの後の同じ行へ置くと本文へ吸われるコメント（囲みコメント・複数行のコメント．`// a` の後の `/* b */` / `/* b↵c */`）は，其の行の直後の独立した行へ順を保って置き，其の行で其の後に続くコメントも続けて置く．次の巡は独立した行のコメントを，後に閉じ字句が続けば塊の末尾のコメント，其の他は後の構文の先行コメントと読む為，空行を挟んで後に別の構文が続く時は其の構文の前（空行の後）へ置く．行の前へ回す行内の行コメントは行末に無い為，此の判断に数えない．
- 行内のコメントを置くと値や描画が変わる所（JSX の要素の本文，複数行の文字列・ヒアドキュメントの本文，Ruby の埋込ドキュメント）は行内に置けない為，其の外（JSX は最も外の要素の行の前，文字列は其の行の前）へ退避する．

## 3. 処理パイプライン

`Formatter::Format` は本文を参照更新し，結果分類・警告・見送理由・入力の構文破損を `FormatResult` で返す．`TSSource` は構文木とキャッシュを `SyntaxState`，コメント情報を `AttachmentState` に保持し，木の差替を `ReplaceTree` へ集約する．

```
入力(Source, Language, MaxChars)
	│
	├─ § 3.0 早期返戻ガード（Unknown 分岐）
	├─ § 3.1 入力バイト検査 → 改行の正規化 (Preprocess) → 初回構文解析（TSSource の構築）
	├─ § 3.2 入力ガード（言語別，SyntaxCheck）
	├─ § 3.3 AttachComments：コメント分離 → SuspendAttachments
	├─ Python の行継続の結合・１行に並べた文の展開（見出行の本体・`;` 区切）／Python・Ruby の括弧内継続行平坦化／Kotlin の改行を跨ぐ継ぎ目の区切り
	├─ § 3.4 ApplyConsolidated：編集収集 → 一括適用
	│	ApplyBraceEdits：冗長ブレース除去・宣言本体への付与（§ 3.4.2，行幅に依らない為 EditPass が担う）
	├─ § 3.5 NormalizeStructured：構造再構築
	│	又は NormalizeInlineSpaces（Python）
	│	ResumeAttachments：最終 AST への再束縛
	│	ApplyRubyModifierForm：Ruby の修飾子形式への変換
	│	ApplyNamedImportSort：JS / TS の名前付 import 指定子の整列
	├─ § 3.6 ApplyVarDeclMerge：宣言統合・分割
	├─ § 3.7 LineSplit：行幅超過のブレース付与 → 行幅整形 → else / while 結合
	│	Python は式の括弧付与・折返．CSS / HTML は対象外
	├─ § 3.8 ApplyDocComment：文書化コメントの生成・補正
	├─ § 3.9 FinalizeLayout：インデント・空行・コメント復元
	├─ § 3.10 Postprocess：言語固有の補修と行末空白除去
	├─ § 3.11 後処理 ERROR ガード → 原文返戻
	└─ § 3.12 LintPass::Run（--no-lint で省略）
```

### 3.0 早期返戻ガード

ファイル拡張子・言語識別子が未対応の `Lang::Unknown` は，AST 構文解析を行わず無加工で返す（§ 1.1 の対象外）．

### 3.1 初回構文解析

- **16 MiB を超えるソース**：整形の対象外とする．並列整形で同時に保持する入力の合計も 16 MiB 以内とし，上限に近い１件は単独で処理する．途中で位置の範囲を超えた場合も原文を保って失敗を報告する．

通過した入力を `TSSource` コンストラクタへ渡して構文解析し，以降の工程で AST とソース文字列を共有する．

- **Java の字句化前 Unicode エスケープ**：javac は字句化の前に `\uXXXX` を文字へ展開する（JLS 3.3）が，構文解析器は展開しない．文字列・文字リテラルの中で区切りや逃避を作らない文字，コメントの中でコメントを閉じない文字へ展開する物は字句の境界を変えない為に其の儘保ち（`"caf\u00e9"`），其れ以外（コメントを閉じる `// \u000a code();`・リテラルを閉じる物・コードの中の物）は javac と同じく展開してから解析し直す．展開前の構文木は，先に在る展開が字句の境界を変えると其れ以降の場所を読み違える為，展開が要る時は全て展開した原文を解析し直して場所を判定する．構文解析器は文字列リテラルの中の u を重ねた逃避（JLS が許す `\uu0041`）を逃避と読まない為，解析し直す場合にリテラルの中へ保つ逃避は u を１個に揃える（値は変わらない）．桁不足と，リテラル・コメントの外で対を成さないサロゲートは javac が拒む字句誤りとして原文返戻する（リテラル・コメントの中の対を成さないサロゲートは其の儘の値で正当）．
- **改行様式の混在（CRLF と裸の LF）**：リテラル（文字列・ヒアドキュメント等の逐語保持する葉と PHP の地の文）の内側の改行は値其の物の為に原文の儘保ち，其れ以外の CRLF を LF へ揃える．書戻は LF の儘とする（CRLF 統一の原本だけ CRLF へ戻す）．CRLF 統一の原本は CRLF を全て LF へ畳んで整形し，書戻で全ての LF を CRLF へ展開する為，文字列の中の単独の CR（`"x\r"` の直後の CRLF 等）も原文の儘戻る．改行様式を揃えた事自体も整形の結果で，他に変更が無くても書き戻す（`--check` は要整形と報告する）．
- **単独の CR**：C / C++ / Java / Swift / Python は単独の CR も行の終わりに読む（Python は読込時に LF へ変える）為，LF と同じ意味として LF へ揃える（改行様式の混在する原本でも，CRLF の CR と区別の付く正規化の前に揃える）．文字列・生文字列（C++ の `R"(a<CR>b)"`）の中の単独の CR は値其の物の為に保つ（`Preprocess::CollectLiteralRanges`）．C# は U+0085・U+2028・U+2029 も行の終わりに読む（tree-sitter-c-sharp は行コメントの続きと読み，後続のコードをコメントの本文と取り違える）為，リテラルと囲みコメントの外の其れらを LF へ揃える．構文解析器はコメントの中の CR で行を終えず，後続のコードをコメントの本文と取り違える．Java の `\u000d` も同じく LF で書く．
- **NUL バイト (`\x00`) を含むソース**：NUL を字句として受理しない文法（C・Go・Python 等）は其処に `ERROR` を立てる．構文解析器が構文誤りを検出した入力の為，原文返戻する（部分整形も不動点に到達しない）．受理する文法（Rust・Ruby・PHP 等）は通常通り整形する．

- **C / C++ 行継続（`\` + 改行）**：字句化より前に行を繋ぐ（翻訳段階２）だけで字句にも意味にも痕跡を残さない為，同じく取り除いて１論理行へ繋いでから解析する（規約 2.3 の行継続の禁止）．`\` と改行の間の水平空白も GCC・Clang・C++23 と同じく行継続とする．前処理指令も１行の儘整形し，行幅を超えても分割しない．生文字列リテラル（前処理指令の本体の中を含む）の内側は段階２が取り消され字面が値其の物の為に残し，囲みコメントの内側もコメントの字面を保つ為に残す．行コメントの中の行継続は次の行をコメントの本文へ取り込む物で，取り除いて其の意味の儘の１行にする（残すと空行の除去等で後続の文がコメントへ入る）．字句の境界は構文解析の前に原文の字面で読む（`EditPass::PrepareCSource`：文字列・文字・生文字列リテラル，`#include <…>` の見出し名，コメント，前処理数の桁区切り `'`）．
- **C / C++ 前処理指令の本体のコメント**：tree-sitter-c は指令の本体（`preproc_arg`）で `/*` を文字列の中でもコメントの始まりと読み（`#define GLOB "src/*.c"`），本体の途中のコメントの後の字句も読めない（`#define T 1 /* y */ + 1`）．指令の中のリテラルの `/*` は `*` を原文に無い制御文字へ置き換えて解析させ，整形後に戻す．本体の途中の囲みコメントは本体の最後の字句の後ろへ移す（コメントは空白１個と同じ意味で，移動は § 1.2 が許す）．行の途中の `#` は前処理指令ではない（`#define STR(error) #error`）．
- **C / C++ の文字列化するマクロの実引数**：`#引数` は実引数の字面を文字列にする為（`#define S(x) #x` の `S(a+b)` は `"a+b"`），同じファイルで `#引数` を使う関数形式マクロと，失敗時に式の字面を表示する `assert` の実引数は，空白・字面・改行を原文の儘保つ（編集・構造化・行分割の何れも掛けない，`TSSource::CollectMacros` / `StringizesArguments`）．他のファイルで定義されたマクロは判別出来ない．
- **C / C++ の `extern "C"` の前処理の条件の囲み**：共通ヘッダの定型（`#ifdef __cplusplus` の中の `extern "C" {` と，別の条件の中の対の `}`）は波括弧が前処理の条件を跨ぐ為，解析器が読めない．前後の空行を除いて前処理の条件（`#if` / `#ifdef` / `#ifndef` 〜 `#endif`）の唯一の行に置かれ，開きと閉じが順に対を成す物だけを，原文に無い制御文字を印とした指令（`#pragma <印>O` / `#pragma <印>C`）へ置き換えて解析し，整形後に `extern "C" {` / `}` へ戻す（`EditPass::MaskLinkageGuards` / `RestoreLinkageGuards`．後続のコメントは残す）．
- **Ruby の埋込ドキュメント（行頭の `=begin` から行頭の `=end` 迄）**：tree-sitter-ruby は本文中の最初の `=end` の字面で閉じるが，Ruby は行頭の `=end` でのみ閉じる．早く閉じると残りの本文をコードと読んで整形し構文を壊す為，本文中の `=end` の `=` の直後へ原文に無い制御文字を挟んで解析し直し，挟んだ文字はコメントの分離で本文から除く．整形後の構文検査（§ 3.11）も同じく印を挟んだ木で行う．

再帰の深さが `RecursionGuard::MaxDepth` を超えた処理は `Parallel::RunOnFreshStack` で続行する．記憶域・走脈を使い切った場合だけ原文を保って失敗を報告する（§ 4.1）．拡張子から C / C++ が確定しないヘッダは，C++ の解析で破損数が減る場合だけ C++ へ切り替える．

### 3.2 入力ガード（言語別）

言語別に AST を検査し，整形が破壊的に為り得る入力を除外する．該当時は原文返戻．本検査は構文破損と各言語の固有条件を同一 AST の走査で収集する．構文エラー（`ERROR` / `MISSING`）に依る原文返戻は § 1.1 が許す．解析器の初期化失敗は整形の判断ではなく実行環境の失敗である．

- **解析器の初期化失敗**：文法と実行時ライブラリに互換性が無い等，構文木を取得出来ない場合は `parser initialization failed` として原文返戻する．
- **入力の `MISSING`，又は Python / Ruby / HTML / JSON の許容対象外の `ERROR`**：字句の欠落，又は本文の構造を信用出来ない入力として原文返戻する．JSONC の末尾コンマだけは削除して整形を続ける．Ruby は並べた式を実引数と読む為，誤読した木で行を繋ぐと別の呼出に化けて構文検査でも見付からない．JavaScript / TypeScript も JSX コンテナ内の `ERROR` は原文返戻する．閉じない文字列（入力途中の `"abc`）は後続を文字列の中身と読んだ木で，部分整形がファイルの残りのインデント・中身を崩す為，全言語で原文返戻する（同じ行に閉じの引用符が有れば，解析器が中身の記法を読めなかっただけで文字列は閉じて居る）．PHP も地の文（出力其の物）を持つファイルの `ERROR` は，壊れた木の部分整形が地の文のインデント・改行を動かして出力を変える為，原文返戻する．解析器の未対応構文に由来する許容対象は `IsToleratedBreak` で除外する．文字列リテラル直下の `ERROR` も内容の解釈失敗として除外する．此れらに該当せず，`ERROR` だけを持つ入力は部分整形を許容する．

### 3.3 `AttachComments`（コメント分離）

全コメントをソースから除去し，AST ノード ID に紐付けて `TSSource` 内部の `LeadingByNode` / `TrailingByNode` マップに保持する．ソース削除後は AST を再構文解析し，紐付はバイト位置 + 親型名のスナップショットを介して新 AST 上で復元される．

スナップショットの経路は（型，`name` 場の識別子，同名兄弟内の通し番号）の列で，識別子はソースから読む．木とソースは常に同じ時点の物でなければならず，片方だけ進んだ状態で採ると識別子が別の範囲を指し，錨を見失った紐付が祖先へ寄って位置が動く．此の整合は `TSSource::GetMutableTree` が担保する — 木を直に書き換える唯一の入口で，返す前にスナップショットを確定させる為，呼出側が順序を誤りようがない．Ruby の末尾の式へ付与する `return`（§ 3.4）は式を `return` と `argument_list` の２階層下へ移す為，再束縛では節（`rescue` / `ensure` 等）を除いた末尾の `return` が包む唯一の式を直下の子としても辿る（見失うと紐付が祖先へ寄り，コメントが本体の先頭又は末尾へ移る）．

- **HTML**：コメントは文書の節点（DOM に `Comment` として残り，スクリプトから読める）で，取り出すと前後の本文と空白が繋がり，文字参照の読み（`&cop<!-- c -->y` が `&copy`）や描画される空白が変わる為，分離せず文書の中の位置に留める（`Preprocess::PrepareHtmlComments`）．本文の表記（読点・句点・空白）だけを其の場で正規化し，句点では改行を作らず読点へ退避する．子の境界の判定では，コメントは描画されない子として扱う（§ 3.5.1）．埋込 `<script>` の JavaScript / `<style>` の CSS は `raw_text` から個別に構文解析し，内部コメントを正規化する．埋込言語の本文は HTML の構文木では不透明な生テキストとして扱い，HTML の整形判断に用いない．
	- 内容を文字として読む要素（`<textarea>` / `<title>` / `<xmp>` / `<plaintext>` / `<iframe>` / `<noembed>` / `<noframes>`）の内側は，構文解析器がコメントと読んでも内容其の物の為，正規化しない．
- **JavaScript / TypeScript の JSX**：JSX を読む文法（JavaScript と `.tsx` の TypeScript）では，`TSSource::AttachComments` 内で本文の意味を確定してからコメントを分離する．隣接する `jsx_text` と `html_character_reference` は連続する本文として扱い，式・要素の境界毎に JSX の行端空白規則を適用する．継続行の先頭空白と改行前の末尾空白を除き，内容の有る行同士を空白で結ぶ．本文内のタブは保持する．半角空白だけの文字列の式（`{" "}` / `{"  "}`）は本文の空白と同じ表示の為，隣接する本文と同じ並びとして扱い（`<p>a{" "}b</p>` → `<p>a b</p>`），式の中のコメントは本文に置けない為に要素を含む文の前へ移す（`=` や `:` の直後の要素の前へ置くと，行コメントが次の巡で要素の本文へ戻る）．錨が JSX の外でも，行分割で行末が要素の本文に当たる（`k: <div>` の次の行に本文）行末コメントは，其の要素を含む行の前へ移す（`LayoutPass::CollectCommentInsertions`）．端の半角空白・タブ（空白の数値文字参照 `&#32;` / `&#x20;` / `&#9;` 等を含む）は原文に無い私用領域の文字を印にして保ち（`TSSource::GetJsxBlankMark`），其の他の空白（NBSP 等）は何方の処理系も落とさない文字参照にする．空白だけの本文の並びは展開の内容子に数えない（`<p> {x} </p>` は１行の儘）．整形後（`Postprocess::FixJsxEdgeSpaces`），改行に接しない印は空白へ戻し，改行に接する空白は `{" "}` で保つ（文字参照は Babel が復号してから行端の空白として落とす為．続く空白と印は最後の印迄１つの式に纏める：`{"  "}`）．タブは Babel が本文のタブを空白として描画し式と表示が異なる為，改行を詰めて隣の子へ密着させる（`a	{x}`）．行端の扱いが TypeScript と Babel で分かれる本文（行端の全角空白・NBSP・`\v` 等，行端の空白の文字参照，U+2028 / U+2029）を持つ要素は（`TSSource::HasDisputedJsxText`．TypeScript は行端の空白を全て落とし文字参照を落とさず，Babel は文字参照を復号してから半角空白とタブだけを落とす），子の並べ方を変えると何方かの表示が変わる為に正規化も構造化もせず原文の並びで保ち（インデントだけを揃える），開きタグの `>` の後でも割らない．連続本文と文字参照の間へ改行を挿入せず，子文字列を区切る空の式は保持する．
- **CSS / SCSS**：コメントは字句を生まない為，分離の跡では英数字同士だけを区切る（CSS の `.a/**/.b` は `.a.b`）．Sass はコメントを空白と読む為，SCSS の選択子の中は前後が空白でなければ区切る（`.a/**/.b` → `.a .b`．CSS と SCSS は拡張子・言語 ID で見分ける：`Lang::IsScss`）．選択子の中のコメントは，錨の前へ戻すと選択子の字句の間へ入る為に規則の前の行へ移す．数値と単位の間のコメント（`0/* c */auto` / `10/* c */%`）は値を含む節点の末尾コメントとする．値の中のコメントの後に空白無で符号付の数が続く物（`1px/* c */-2px` / `1px/* c */+2px`）は，Sass が加減算と読む（空白が有れば符号）為に後ろへ密着させ，前も空白無の物は前にも密着させる（前へ空白を置くと Sass が非推奨の読み（将来は並び）にする：`CommentAttach::IsGluedAfter` / `IsGluedBefore`）．Sass は左の値の直後の空白の有無で読みを決める為，空白を挟んでコメントが並ぶ時（`1px/* c */ /* d */-2px`）も，並びが符号付の数へ密着して終われば前が空白無のコメントを前に密着させる．宣言の値のコメントの隣を解析器が識別子と読んだ物（`a/* c */b`）は，外すと値を別の種別で読み直して錨を失う為，宣言の末尾コメントとする（`a b; /* c */`）．引用符の無い `url(…)` の中身はコメントの形（`/*`）も含む生の字面の為，コメントとして分離せず，インデントを求める括弧の対応でも閉じ迄を読み飛ばす（閉じない `url(a/*b)` の後のインデントを保つ）．
- **其の他の言語**：`TSSource::AttachComments` を呼び出す．
- **コメントの本文の表記**：規約第８章の読点（`、` → `，`）と句点（除去して後続の文を次の行へ送る．次の行に作用する指令の行（`// eslint-disable-next-line x -- 一文目，二文目`．括弧の中（全角の丸括弧，又は同じ行の半角の丸括弧の中）の句点も，分けると括弧の対が行を跨ぐ為に分けず読点へ退避し，閉じ括弧の直前の句点（対の開きが無い `甲。）` を含む）は除く．閉じの記号（`*/` / `-->`）に接する文末の句点は，除くと本文と閉じの記号が接する為に空白へ置き換え（`/* 文。*/` → `/* 文 `例：９５０`，`関数(foo)を` → `関数 (foo) を`，`値(ドメイン)ごと` → `値 (ドメイン) ごと`，`/*  コメント  */` → `/* コメント */`）．コード（コードスパン・コード区画）・引用（鉤括弧・二重鉤括弧・隅付括弧と，同じ行で閉じる `"…"` / `'…'`．英文の省略の `don't` の `'` は開きに為らない）・リンクの記法（`[説明](先)`）・文書化コメントの要素の記法（`<summary>`）・素の URL とファイルの経路（`://` を含むか，半角の字で始まり，ASCII の字だけの後に `/` を含む空白で区切った塊．全角の字の直後に空白無で始まる物（`資料はdocs/…`）も前へ空白を置いて塊と読む．最初の `/` の後で ASCII の英数字の次に全角の字が来る所は経路の後に続く本文の為，其処で塊を終える：`src/a.cppです` → `src/a.cpp です`，`docs/設計書.mdを参照` → `docs/設計書.md を参照`．英数字以外の ASCII の後（`src/a.ts(旧版)を` / `x/y=座標`）と URL は，経路の終わりを決めれない為に塊の全体を保つ）・シバンと指令（`//go:generate` 等の小文字で始まる語の指令と TS の `/// <reference …/>`）の行・行頭のインデントとマーカ・箇条書の記号と番号と引用の記号（`- ` / `1. ` / `> ` / `❌ `）と其の後の空白・悪い例を示す `❌` の行・表の `|` の両側は触らず，閉じの記号（`*/` / `-->`）の前・コメントの中の `//` の前と保護した字（コードスパン等）に接するスペースは除かずに詰めるだけにする．行コメントのマーカの後の密着が要件の印（`///` / `//!` / `//#` / `//@` / 指令，`#!` / `##` / `#:`（Ruby の rbs-inline の型の注釈と Python の Sphinx の属性の説明）/ `#--` / `#++`（Ruby の文書化の停止と再開））の後へは空白を置かない．英字を含む半角の語の後に全角の語が続く所でも，全角の語の直後に空白無で始まった半角の並び（`値は${x}です` / `言語.NETを`）は前に置かない為に後ろにも置かない．数字だけの語と全角の語の間（`16進`）と１字の数量の英字と単位の間（`N回`．規約は字の全角化を求め，スペースでは直らない），矢印・ダッシュの前後と章の番号の後（`第１章 基本方針`．規約がスペースを許す）も触らない．半角の区切子の前と半角の括弧の内側は，コメントに地の文で書いたコードの例（`a ? b : c` / `for(x : xs)` / `while ( )`）と見分けれず，詰めると例が変わる為に触らない．ハングルは表音文字で半角の為，韓国語の分かち書きのスペースは保つ．数値との間に空白を置かない `%`，`‰`，`°` / `′` / `″` の前へは置かない．
- **処理系が読むコメント**：本文の正規化（読点・句点・空白・行コメントの記号の後の空白）を掛けない．Rust の文書化コメント（`///` / `//!` / `/** */` / `/*! */`．`#[doc]` 属性としてコマンドの説明文等に出る），Go の `import "C"` の直前のコメント（cgo が C のソースとして翻訳する前文）と，Go の例の関数（`func Example…`）の出力のコメント（`// Output:` / `// Unordered output:` で始まる行コメントの群．`go test` が本文を出力と照合する）は本文其の物を保ち，`*` で始まる継続行を `/**` の `*` の位置へ揃える配置もしない（`CommentAttach::IsVerbatim`．cgo の前文の `"a\` の次の行の `*b";` は C の文字列の続き）．其の他のコメントでも，同じ行で閉じる引用符の中（`"…"`）と注釈の引数（`@Route("…")` / `@Assert\Regex(…)`．PHP の枠組が実行時に読む）は字面の儘保つ．

分離より**前**に置けるのはコメント自身を対象とする処理と，分離で字句が繋がる箇所の区切り・解析器の読違を原文の読みへ揃える処理だけとする（`EditPass::ApplyJsJoints` / `ApplySwiftMisreads` / `ApplyKotlinSemicolons`．tree-sitter-kotlin の走査器は，改行の後の囲みコメントに続く語が `else` / `as` / `where` / `by` / `!=` と同じ字で始まる別の語（`abstract` / `enum` / `when` / `!flag` 等）の時にコメントを自動の `;` の字句へ呑み込み，コメントが構文木に現れない為，字句の間の隙間に残る `/*` の前の字句の後へ `;` を補って読み直させる．型の本体の最後の成員の後に同じ行で `}` が続く時（`class C { val a = 1; val b = 2 }`）も自動の `;` を読めずに成員を ERROR に包み，原文の隙間を写した結果が `}` を次の行へ移した次の巡で変わる為，本体の子が全て健全な成員（又は其れだけを包む ERROR）なら最後の成員の後へ `;` を補う．補った `;` は整形が外す）．単一行の囲みコメントの句点の分割は，行末へ置く時に分けない本文と使い分ける為に分離の後の本文の正規化で行う．コメント以外を書き換える処理を前に置くと，AST に並ぶコメント節点で子の位置がずれて § 1.2 を破る為，分離の**後**へ置く．

直後に `Src.SuspendAttachments()` で紐付を一旦凍結し，§ 3.4 / § 3.5 区間中の AST 改変毎の再束縛コストを回避する．`ResumeAttachments` で最終 AST へ**１回だけ**再束縛する．

#### 錨解決ルール

各コメントを以下の順で名前付非コメントノードに紐付ける．

1. **行頭〜行末コメント** (`Leading`)：直後の兄弟 → 直前の兄弟 → 祖先兄弟 → ルート（`Trailing` 化）．塊の末尾のコメント（コメントの後に続く字句（親の中に無ければコメントと共に終わる祖先の後の字句）が閉じ字句（`}` / `)` / `]` / `end` / PHP の代替構文の `endif` / `endforeach` / `endfor` / `endwhile` / `endswitch` / `enddeclare`）の物，又は閉じ字句を持たない文の並び（Swift / Kotlin の `statements`・Python の塊）の最後．Ruby の最後の `when` / `elsif` / `rescue` / `in` の本体の末尾は `case` 等の `end` の前に当たる．Ruby の節（`elsif` / `else` / `rescue` / `ensure` 等）と閉じの `end` だけの空の本体（`while a` の後の `do`）の前も手前の本体の末尾とする）は，直前の兄弟の後の独立した行へ置く末尾コメントとし，直前の兄弟の始まりの行のインデントで塊の末尾に留める（`CommentAttach::IsOwnLine`．直前の兄弟の前・閉じ字句の後の節・外の文へ移すと別の文の説明に為る）．直前の兄弟が節（`case 1:` / `default:` 等・PHP の代替構文の本体 `colon_block` と其れを持つ `else` / `elseif` の節）なら，節の最後の子（本体の最後の文）の後へ置いて本体のインデントに揃え，本体の文の無い節（見出しの字句だけの Java の `default:` を含む）は節の後へ見出しと同じ深さで独立して置く（`CommentAttach::ForcesOwnLine`）．本体の文の無い Ruby の構文・節（`if a` / `def f(a)` / `class A < B` / `rescue A` / `when 1` / `while a`）のコメントは，本体（`then` 等）でなく構文の直下の子で直前の兄弟が見出しの子に為る為，見出しの後へ見出しと同じ深さで独立して置く．塊の中の兄弟の無い Ruby の節（`else` / 例外を略した `rescue`）のコメントは，下の空の塊のコメントと同じく節自身の末尾コメントとし，節は見出しの後へ同じ深さで独立して置く．PHP の代替構文の本体の文の無い節（`if($c):` / `elseif($b):` の後のコメント）は，本体の `colon_block` が `:` だけでコメントを中に持たずコメントが構文の直下の子に為る為，同じく節の後へ見出しと同じ深さで独立して置く．見出しの子を持たない Ruby の `begin` の空の本体のコメントは，節点が `end` を含み見出しの後へ置けない為，下の空の塊のコメントと同じく `end # c` とする（`begin # c` の行末のコメントも，前後に名前付の子が無く前の文へ遡ると別の文の説明に為る為，同じく `end # c` とする）．構文を１行に畳めば何れも行末へ置く（`while a do end # c`）．閉じ波括弧で終わる塊と後の節（`} // c` の次の行に `else {` / `catch(e) {`）の間の独立した行のコメントは，節が閉じ波括弧の行へ連なる為，節の本体の最初の文の先行コメントとし（本体の文が無ければ節の儘），閉じ波括弧の後の行末コメントより前に出ない様にする（§ 1.7）．直前の兄弟とコメントの間に開き波括弧の字句が在る物は構文木の字句で判る（コメントの本文の `{` を判断に使わない）．整形で直前の兄弟の後に同じ行のコードが続き（波括弧の除去で `} else` に為る），其の最後の行が閉じ括弧で始まる時は，其の行の前へ錨と同じ深さで置く（塊の末尾の儘）．整形で直前の兄弟が行の途中から始まるか後に兄弟が続く時（波括弧を除いた `if(a) b();` の本体・後置の条件へ畳んだ Ruby の `b if a` の後に文が続く物）は，独立した行へ置くと外側のインデントで次の文のコメントに見える為，行末へ置く（`if(a) b(); // c`．行末へ置けない複数行のコメント（Ruby の `=begin`）と，本体の文の無い節のコメントを除く．Ruby の節の前の最後の文は後に節が続いても塊の末尾とする）．独立した行へ置いたコメントの後のコメントも，行末へ置くと前のコメントより前に出る為に独立した行へ置く．直前の兄弟が文の末尾の値（Ruby の `return` を補った文の値 `2`）なら，同じ所で終わる文（文の並び・本体・節・制御構文の直下の子）で判定する．中身がコメントだけの空の塊・括弧のコメント（塊の中に兄弟が無い物．見出しの子とコメントの間に開き括弧が在る物を含む）は，次の兄弟（後続の枝・後の文）・見出しの子・外の構文へ運ぶと別の枝・文の説明に為る為，塊を持つ構文自身の末尾コメントとし，コメントの数・後続の枝の有無に依らず構文の最後の行の行末へ連ねる（`} catch {} // A // B`．`if(a) {} else {` の空の then のコメントは else の本体の後の `} // c`．括弧の節点は祖父が其の構文で，文の並びに直に置いた塊は塊自身，本体を括弧で包まない構文（Ruby の `begin` / `else` 等・Swift / Kotlin の波括弧を直に持つ構文）は親が其の構文）．コメントの後に続く字句が閉じ字句なら，次の名前付の子（波括弧を直に持つ構文の閉じの後の節）でなく塊の末尾とする．次の行に作用する指令（`// @ts-expect-error` / `// eslint-disable-next-line` 等．`DocSig::IsNextLineDirective`）の次の行が閉じ字句で始まり同じ行にコードが続く時は，其のコードの先行コメントとし（錨が `} else { … }` / `} catch (e) { … }` の節なら，見出しは展開で本体と別の行に為る為に本体の塊の最初の文），配置の段は錨が行の途中なら錨を含む行の前へ置く（閉じ括弧で始まる行の前も錨と同じ深さ．錨の後の行の前や閉じ括弧で始まる行の末尾へ置くと別の行へ作用する）．
2. **行中コメント** (`Inline`)：後ろに同じ行のコードが続くコメント（行頭の `/* c */ x();` を含む）．CSS の宣言の値のコメントは上の CSS / SCSS の項に従う．区切子 (`,` `;`) や閉じ括弧の直前なら直前の兄弟の末尾コメント（空の括弧の中 `foo(/* c */)` は祖先から遡った直前の兄弟＝括弧の前の被呼出側の末尾コメント．祖先の後の兄弟へ遡ると次の文の説明に化ける），其れ以外は直後の兄弟の先行コメント（説明対象が一つ後ろへずれない様にする．行頭の物を直前の兄弟の末尾コメントにすると，前の文の行末へ移って前の文の説明に読める）．
3. **行末コメント** (`Trailing`)：見出しの字句（`try {` / `} else {` / `default:` / Ruby の `else` / Python の `finally:` 等）の直後の行末コメント（同じ親の名前付の子が前に無く，親の字句の後に在り，後に名前付の子が続く物）は，見出しの行の説明の為，本体の最初の要素の先行コメントとし，配置の段が見出しの行の行末へ置く（`CommentAttach::IsHead`．錨が行頭なら錨の前のコードの終わり，行の途中（波括弧を外した本体・畳んだ節）なら錨の行の行末）．波括弧を直に持つ構文（Swift / Kotlin）の閉じ波括弧の直後の行末コメントも，閉じ波括弧の行へ連なる次の節の見出しの行の説明として次の節の本体の最初の要素へ紐付ける（`} catch { // c`）．行末の次の行に作用する指令は，次の行に始まる要素（`f(1, // @ts-expect-error` の次の行の `"t");`・`x = 1; // eslint-disable-next-line` の次の行の文・次の行の閉じ字句の後の `) h(1);` の本体）の先行コメントとして同じく扱い（前の要素の末尾コメントにすると，整形が次の要素を同じ行へ畳んだ時に行末の指令が更に次の行へ作用する），錨が行の途中へ移れば錨の行の前へ，錨の行との間に空行・自動の文書化コメントが入れば錨の行の直前へ置く．次の行が閉じ字句だけ（`g(1, // @ts-ignore` の次の行の `);`，`}` の前の独立した行の指令）なら前の要素の末尾コメントとし，整形で其の行が畳まれて次の行がコードに為れば錨の行の前へ置く（`CommentAttach::IsCloserDirective`）．空行・コメントの行の前の指令は作用して居ない為に末尾コメントの儘とする．其の他は直前の兄弟（無ければ祖先から遡った直前の兄弟）の末尾コメント．閉じ波括弧より後の行末コメント（`for(…) { a(); b(); } // c`）は，解析器が塊の子として取り込むか（JS / TS），塊の閉じを直接の子に持つ構文の後の兄弟とする（Swift）が塊の中身では無い為，塊の中の最後の文へ降ろさず塊・構文の末尾コメントとする（`} // c`）．空の括弧の並び（`def f() # c` の `()` / `[]() { // c`）は冗長として外れ得る為，同じ行に在る直前の兄弟（名前・捕捉）へ紐付ける．直前の兄弟が無い物（`xs.map() { // c` / 外れない `() => { // c`）は括弧へ紐付け，外れた時は再紐付が直前の要素へ寄せる．中身の無い括弧の開きの直後の行末コメント（`return [ // c` の次の行に `]`．中身が有れば上の見出しの字句の後のコメント）は，直前の兄弟を親から遡ると前の行の別の文に届く為，コメントの行から始まる最も外の祖先が文（文の並び・根の直下）なら其の文の末尾コメントとする（行分割が折り返した `.map { // c` の呼出の接尾辞や `) if( // c` の内の見出しの様に祖先が文に届かない物は，同じ文の一部として直前の兄弟の儘とする）．遡りは文の並び（関数・クロージャの本体）で止め，同じ行に始まる外の文（`return { return [ // c` の外の `return`）へは移さない（外の文の末尾コメントは本体の閉じの後へ出る）．Allman 形式の `{ // c` の様に括弧を持つ構文に直前の兄弟が在る物は，同じ構文の一部の其の兄弟の儘とする．
4. **`} ... else` の中間コメント**等は同一行末尾として直前の同行子孫に降下して紐付ける．
5. **JSX 内コメント `{/* ... */}`**：コメント本文だけを分離し，子文字列の境界を保つ空の式へ紐付ける．行コメントはブロックコメントへ変換して保存し，最終復元で `{}` の内側へ戻す．空の式はコメントの有無に依らず保持し，展開の内容子数には数えない．

波括弧除去で消える透過包装（`NodeKind::TransparentWrap`）へ紐付いた先行コメントは，コメント以外の最初の名前付子へ降ろす．コメント節点は分離後に消えて錨に為らない為，降ろす先に含めない（含めると再解析後に錨を見失い，コメントがファイル末尾へ逃げる）．末尾コメントは包装に留める：包装が残れば閉じ括弧の行（`} else { // c`）に置かれ，降ろすと中の文の行へ移って次の巡で位置が動く．包装が消えれば再紐付が包装を透過して親（制御構文）の末尾コメントに為る．但し閉じの字句を持たない文の並び（Swift / Kotlin の `statements`）と末尾の改行迄を節点に含む物（Swift の文）は，整形後の終わりが次の行の頭に来てコメントが閉じ括弧の行へ移る為，行末・行内のコメントも最後の文へ降ろす（`{ $0 > 1 /* c */ }`）．

外れた丸括弧の対の錨は再紐付で見失う為，錨の種類（`AttachSnapshot::Paren`）で寄せる先を決める．中身を持つ括弧（`if (a): # c` の条件・`(x) => { // c` の仮引数・`(1, 2)` の組）と空の実引数で終わる呼出（Swift の `xs.map() { // c`）は，中身・被呼出側が同じ順番の子として錨の位置を占める為に其の子へ，空の括弧は直前の要素（其の順番の前の子，無ければ親から遡った直前の要素）へ寄せる（親へ寄せるとコメントが親の構文の末尾へ移る）．外れた括弧の中の子を錨とするコメント（`foo(a, (/* c */ b))`）は，括弧の段を素通りした次の段を括弧の段の順番で解決する（括弧の中の順番の儘では親の同じ型の最初の子 `a` へ移る）．外れ得る包装（括弧・波括弧の塊等）の段は，同じ型の前の兄弟だけが外れると同じ型の中の通し番号が詰まり後の兄弟を選ぶ為，親の名前付の子の中の順番の位置の子と照らし，其の子が別の型なら外れた物として素通りする（`c ? (items.map(…)) : (<p/>)` の最初の括弧が外れても，其の中の錨を後の `(<p/>)` へ移さない）．後に節が続く外れた波括弧の塊（`if (a) { g(); } // c` の次の行に `else`）の錨は，中身の文が同じ順番の子として錨の位置を占める為に其の文へ寄せる（`if(a) g(); // c`．親へ寄せるとコメントが else の枝の後へ移る）．構文の最後の塊のコメントは構文の終端コメントとして構文へ寄せる．

構文解析器が本文を持たないコメント節点を作る場合（Kotlin の走査器は囲みコメントの後の空白を読み飛ばす時に字句の始まりを動かし，幅０のコメントを作る）は，紐付ける本文が無い為に扱わない．其のコメントの本文は構造の再構築で失われる（§ 1.2 の許容する消失）．

最終退避経路としてルートへ紐付ける事に依り，**ソース残置を発生させない**（コメント非依存原則を担保）．

#### １行に並べた文の展開（Python）

複合文の見出しの `:` と同じ行に置いた本体（`if x: a = 1`）は次行へ移して１段深くインデントし，`;` で並べた単純文（`a = 1; b = 2`）は本体のインデントで行毎に分ける（`StructurePass::ExpandPythonInlineBlocks`）．行末の `;` は何も区切らない為に除く（規約 2.15）．何れも元の改行の有無で出力が変わらない様，括弧除去等の前に行う．

#### 括弧内継続行の平坦化（Python・Ruby）

冗長括弧の判定（§ 3.4.1）が元の改行に左右されない様，括弧除去の前に括弧の内側の継続行を畳む（`StructurePass::FlattenBracketContinuations`）．文字列・ヒアドキュメント・Ruby の区切り文字付リテラルの内側は保つ．Ruby は文法が改行を文・見出しを終える字句として子の間と前後に置く節点（`NodeKind::RubyTerminatorHost`：文の並び・ブロック・分岐・定義等）の直下の改行を，括弧の内側でも保つ（畳むと `puts v puts v` の様に文が繋がる）．其れらの子の内側の改行は式の継続の為，括弧の内側なら畳む．

### 3.4 `ApplyConsolidated`（統合エディット）

[`EditPass::CollectConsolidatedNamedWalk`](../src/Pass/Edit.cpp) で AST を走査し，収集した編集を**１回の適用（再構文解析も１回）へ統合**する．個別に `Apply` すると都度再構文解析が走り遅い為．HTML は本工程自体を省略する．ルートの名前付子毎に並列走査し，スレッドローカルな `Edits` をマージする．

`EditPass` の定義は，統合走査の `Edit.cpp` と，構文補修・波括弧・式・宣言・Ruby・文書コメントを扱う `EditSyntax.cpp`・`EditBraces.cpp`・`EditExpression.cpp`・`EditDeclaration.cpp`・`EditRuby.cpp`・`EditDocComment.cpp` に分ける．

#### 3.4.1 冗長括弧の保持判定

`(expr)` の括弧を削除すべきかは下記を順に評価し，**１つでも該当すれば保持**する．中身が括弧だけの層（`((x))`）は最も外の層を最も内側の中身で判断し，内側の層は判断に依らず外す（原文の括弧の数に依らず同じ形に揃える：`((a + b)) * c` → `(a + b) * c`，`((x))` → `x`．型の括弧・Python の組の括弧も同じ）．構文木を信用出来ない所（ERROR の周り）・字面が値に為る所（Python の f 文字列のデバッグの差込 `f"{(x)=}"`）・型の別名の誤読（下の 5）の中の層は纏めずに其の儘判断する．

1. 親が `ParenKeeper` 集合（`if_statement` / `switch_statement` / `cast_expression` / `call_expression` 等）．但し見出しの条件を括弧で包まない言語（Go / Rust / Swift / Python / Ruby）の制御構文（`ParenOptionalHeader`．Ruby は `if` / `elsif` / `unless` / `while` / `until` / `case`）の直下の括弧は冗長の為に保持しない（`if (x) {` → `if x {`）．Go の型名の複合リテラル（`T{...}`．`[]int{...}` 等の型名でない物は衝突しない）と Rust の構造体の式を区切り（実引数・配列・添字・関数の本体等の括弧の中は衝突しない）の外に含む見出しの中の括弧は，`{` が本体の始まりと衝突する為に文法上必須で保つ．Swift の見出しの式（条件・束縛の値・`for` の反復対象・`where` の条件・`switch` の対象）がクロージャを区切りの外に含む時は，其の式の全体を括弧で包む形へ揃え（`if xs.contains { $0 > 1 } {` → `if (xs.contains { $0 > 1 }) {`．Swift は複数行に展開したクロージャの `{` を本体の始まりと読む．`EditPass::ApplySwiftMisreads`），其の括弧だけを保って内側の冗長な括弧は外す（`if (xs.first { $0 }) != nil {` → `if (xs.first { $0 } != nil) {`）．クロージャが複数行に展開する時は，此の括弧も実引数の並びと同じく展開する（`if (` の次の行に式を置き，`) {` の行で閉じる．§ 1.5）．`return` / `throw` / `yield` / `await` の後の括弧も冗長で外す（C++ の `decltype(auto)` を返す関数の `return (x);` は参照を返し，PHP の参照を返す関数の `return ($x);` は括弧で包むと参照を返せない為，何れも保つ）．`for` 文の初期化・条件・更新を包む括弧は構文の括弧ではない為に含めない（JS / TS の初期化の `in` を包む括弧は § 3.4.1 の JS / TS の規則で保持する）．Java の `synchronized_statement`（錠の式の括弧は構文の一部）と PHP の `function_call_expression`（`($o->f)(1)` の括弧を外すと属性の閉包の呼出がメソッド呼出に，`($a ?: $b)()` は結合が変わる）も含む．親が自身の括弧・区切りの直後に置いた括弧（C# / Kotlin の見出しの `if ((a > 1))`，添字の `a[(i)]`，反復の対象の `of (xs)` / `in (xs)` / `: (xs)`，JS / TS の for-in の左辺の `for ((k) in o)`，PHP の foreach の対象の `foreach (($xs) as $x)`）は構文の括弧でない冗長な括弧の為，保持の対象から外して以下の判定へ回す（`if(a > 1)` / `a[i]` / `for(const x of xs)` / `for(k in o)`．C++ の `decltype((x))` は内側の括弧で型が変わる為，TS の for-in の左辺の型の表明 `for ((x as any) in o)` は外すと解析器が読めない為に保つ）．括弧を構文に持たない親の被演算子（C# の switch 式の対象 `(y) switch`，JSX の式 `{(x)}` / `onClick={(() => f())}`，JS / TS の new の名前 `new (a.B)()` / `new (a.b[0])()`，型が基本型・ポインタの C / C++ のキャストの値 `(int)(y)` / `(long)(-y)`）も保持の対象から外して以下の判定へ回す（new の名前は呼出・任意の連鎖を含む物 `new (a.b())()` / `new (a?.b)()` を，キャストは名前の型の `(f)(x)` と呼出の形の `(g())(x)` を，何れも外すと読みが変わる又は呼出と見分けれない為に保つ）．後置の式（メンバ参照・呼出・添字，`PostfixReceiverHost`）の受け手を包む括弧は，内側（括弧層を透過する）が名前・後置の連鎖・字句で閉じるリテラル（`PostfixReceiverChain` と `PostfixReceiverLeaf`）なら後置の演算子の結合が変わらず冗長の為に保持しない（`(a.b).c` → `a.b.c`，`(g()).h` → `g().h`，`("abc").length` → `"abc".length`．`EditPass::KeepsPostfixReceiver`）．Rust の後置の `?` / `.await` / `as`（`RustPostfixHost`：`(a.b)?` → `a.b?`，`(f()).await` → `f().await`，`(a) as u8` → `a as u8`．`as` は前置単項より弱く左結合の為，前置単項と `as` の受け手も外す：`(-a) as u8` → `-a as u8`，`(a as u8) as u16` → `a as u8 as u16`．`(&mut f).await` は外すと `&mut (f.await)` と読まれる為に保つ）と Go の型 switch の `(x).(type)` の受け手も同じ．受け手に置けるかは最上位の種別だけで決めず，最初の子を辿った背骨の全体が名前・後置の連鎖である事を求める（`EditPass::IsPostfixAtom`．tree-sitter-swift は `a + g()` を二項式を被呼出側とする呼出と読み，最上位だけを見ると `(a + g()).h` を外して `a + g().h` に変える）．C++ のメンバへのポインタ `.*` / `->*` は二項の演算子の為に受け手に置けない．引数付の生成（JS / TS / Java / C# の `new A()`）と，数値の後の `.` を小数点と読まない言語（C# / Kotlin / Swift）の数値も受け手に置ける．任意の連鎖（`(a?.b).c` は外すと `.c` が `?.` の短絡へ取り込まれる），引数の無い生成（JS の `(new A).b` は `new A.b` と読まれる）と C++ / PHP の生成，C / C++ の名前・メンバの名前の呼出（`(f)(x)` / `(s.max)(a, b)` は関数形式マクロの展開を止める），Rust / Kotlin / PHP の欄の呼出（`(a.f)()` は欄の持つ関数の呼出で，外すとメソッドの呼出に為る），其の他の数値（JS の `(1).x` は `1.` を小数点と読む）は保つ．
2. 親が `expression_statement` で内側が `ExprStmtLiteral` 集合の場合，又は内側が `ParenInnerNoUnwrap` 集合の場合．`ParenInnerNoUnwrap` は `arrow_function` / `comma_expression` / `lambda` / `lambda_expression` / `list_splat` / `named_expression` / `range_expression` / `reflect_expression` / `sequence_expression` に加え JSX / HTML 要素 (`element` / `jsx_element` / `jsx_self_closing_element`) を含み，括弧を削ると関数引数列化・IIFE 構文崩壊する．加えて親が `fold_expression` の場合も保持．但し右端を貪欲に伸ばす又は呼び出されて初めて括弧が要る式（`GreedyTailExpression`：矢印関数・ラムダ・`if` / `match` / `when` 式・C++26 の反映式 `^^T`．反映式は型の被演算子が後続の `&&` `<` 等を取り込み，`r == (^^int) && t` を外すと `^^int&&` の型に為る）は，括弧が値の全体を包み後に区切り以外の字句が続かない値の位置（`ParenValueSlot`：代入の右辺・実引数・戻値・要素）では外す（`const f = (x => x);` → `const f = x => x;`，`let y = (if c { 1 } else { 0 });` → `let y = if c { 1 } else { 0 };`）．反映式は後続の字句を型へ取り込むだけの為，括弧の直後が区切り（`;` `,` `)` `]` `}`）なら値の位置でなくても外す（`r == (^^int);` → `r == ^^int;`）．名前付の子を２つ以上持つ括弧（tree-sitter-typescript が受理する Flow の型の表明 `(x: T)`）も式を包む括弧でない為に保持する．Swift の演算子の参照（`(^^)` / `(!+)`．解析器は `custom_operator` と読む）も，外すと演算子の字句だけが残って構文が壊れる為に保持する．
3. **C / C++ の C キャスト誤判定回避**：内側が `CCastInner`（`primitive_type` / `pointer_declarator` / `template_type` / `qualified_identifier` 等），又は直後に単項を兼ねる演算子（`-` `+` `*` `&`）が続く名前の括弧（単独の括弧に限る：`((a)) - 1` → `a - 1`．複合代入の `-=` `*=` 等とメンバの `->` は単項を兼ねない字句の為に外し（`(p)->x` → `p->x`，`(b) -= c` → `b -= c`），`&&` は GNU の `&&label`（ラベルの番地）の単項に読める為に保つ）．`(counter_t)-1` を `counter_t - 1` と誤判定する tree-sitter-c のバグ対策．二項の右の被演算子で後に何も続かない名前の括弧（`a + (b)`）はキャストに読めない為に外す．後置の増減の被演算子（`(x)++`）は後の `++` が被演算子を持たずキャストに読めない為に外す（後に `+` `-` `&` が続く `(x)++ + y` も外す）．但し後置の増減の後に間接参照・括弧が続く `(T)++*p` / `(T)--(x)` は，前置の増減を掛けたキャストと読める為に保つ．逆に型名と変数名を字面で区別出来ない C / C++ は `((d) - a)` の中身を `-a` へのキャストと読む事が有り，二項の演算子を兼ねる `-` `+` `*` `&` で始まる値へのキャストを包む括弧も保持する（本当は二項式の場合，外すと其の結合が変わる）．C# は括弧の中が式としても読める名前（`d` / `A.B` / `global::A.B`）又は添字の付いた名前（`d[0]`）で直後が `-` `+` `*` `&` `^` なら二項式と読む為，整形の前に名前を包む括弧を外して二項式として解析させる（`((d) - a) * 2` → `(d - a) * 2`．`EditPass::ApplyCSharpMisreadCasts`）．別名の修飾だけの名前（`(global::A)-a`）はキャストの儘で，末尾が総称の名前（`(A.List<int>) - a`）は括弧を外すと `<` `>` が比較に読まれる為に触らず，其のキャストを包む括弧を保持する．tree-sitter-c-sharp は `out` の無い実引数の `d * a` も `d*` 型の宣言式と読むが，宣言式を置ける実引数は `out` の物と分解の代入の左辺の組だけの為，其れ以外では乗算として `*` の両側に空白を置く（`StructurePass::ReadsAsCsProduct`）．
4. **JS / TS の文頭の読み**：括弧を外すと内側の最左の字句が文頭の塊・宣言・指示と読まれる位置の括弧は保持する（`ReadsAsJsStatementHead`）．式文の先頭の `{` / `function` / `class` / `async function`（`(function() {})();` を外すと関数の宣言），矢印関数の本体の先頭の `{`（`() => ({ id: 1 })` を外すと本体の塊），`export default` の直後の `function` / `class`，文字列だけの式文（`("use strict");` を外すと指示），式文と for-in の左辺の先頭の `let [`（`(let)[k] = v` を外すと分割代入の宣言），for-of の左辺の先頭の `let` と左辺其の物の `async`（`for ((let).x of xs)` / `for ((async) of xs)` を外すと構文誤り）が該当する（`(let).x = 1` / `for ((let) in o)` / `for ((async).x of xs)` は外す）．文の後置の増減は前置へ移して文頭から外れる為（`(let)[k]++;` → `++let[k];`），其の括弧も外す．for-in の反復対象（`in` の後）はコンマ式を括弧無で取る為，其のコンマ式の括弧も外す（`for (k in (a, o))` → `for(k in a, o)`．for-of は取れない為に保つ）．`for` 文の初期化子の中で `in` の二項式を包む括弧（`for(var i = ("x" in o) ? 1 : 0;;)`．外すと for-in の見出しに為る）も保つ．実引数・添字・補間・対の値・計算の鍵・欄の初期化子・関数の本体（`NodeKind::JsInRestoring`）の中は `in` を二項の演算子に戻す為に外すが，配列の要素・展開・仮引数の既定値は TS の構文解析器が初期化子の読みを引き継いで拒む為に保つ（`for(var f = (a = ("x" in o)) => a;;)`）．
5. **Python `type(x).attr`**: 祖先に `type_alias_statement` が有れば保持（tree-sitter-python の Python 3.12 型別名誤判定対策．Python のみ祖先走査）．
6. **Python / Ruby の括弧内改行**：前段の平坦化後も括弧内に改行が残る場合は保持する．但し Ruby の `end` で閉じる構文（`(if x … end)` 等の `RubyBlock`）の中の改行は構文の内側で閉じて継続に関わらず，保つと構造化が１行へ畳んだ後の次の巡で外れる為に数えない（`a: (if x↵1↵end)` → `a: if x then 1 end`）．Python の折返に必要な括弧は § 3.7 で付与する．平坦化は文字列・ヒアドキュメント・Ruby のブロックと区切り文字付リテラル（`%s{…}` / `%r(…)` 等．開きが複数字句で閉じが１字句の為，降りると深さを誤る）の内部へ降りず，ヒアドキュメントの終端タグの後の改行は畳まない．
7. **演算子優先順位**：親演算子の優先度（`OpPrecedence` 表）が内側より高ければ保持．Swift のシフトは比較と同じく結合性を持たない為（`a << 3 >> 2` は構文誤り），同優先度の両被演算子の括弧を保持する．tree-sitter-swift は `!=` `!==` `<=` `>=` を利用者定義の演算子（`custom_operator`）と読む為，字句で比較の格を与える（`(a != b) && c` → `a != b && c`）．ネストを誤る解析器（tree-sitter-python の `a & (b ^ c) ^ d` を `a & ((b ^ c) ^ d)`，Swift の `&&` / `||`，Ruby の修飾子 `rescue`）に備え，括弧の逆側に隣接する演算子が内側より強ければ保持する（正しいネストでは判定を変えない為，全言語で見る）．前置の単項は被演算子の右に演算子を持たない為，右隣を探す時は越えて遡る（`-(a + (b * c))` の内側の括弧は外す）．語で始まり右の被演算子を式の終わり迄取る式（`yield` / `include` / `require` / `print` / `throw` / ラムダ / `return` / `break` / Python の `:=`，`NodeKind::OpenPrefixExpression`）は最も弱い 1，語や記号で前置する単項（C++ の `co_await` / `delete`，PHP の `@`，JS / TS の `await`，`NodeKind::KeywordUnary`）は前置単項の 15 とする（表に載る演算子を持たない式を最も強い物と扱うと `(yield x) + 1` の括弧が外れる）．累乗 `**` の左被演算子の前置単項（`await` を含む）は包む括弧を保つ．累乗は前置の単項より強く結合する為，Python の `-` `+` `~` と Ruby の `-` の被演算子の累乗を包む括弧は外す（`-(a ** 2)` → `-a ** 2`．JS / TS は単項を `**` の左に置けず，tree-sitter-php は `-$a ** 2` を `(-$a) ** 2` と読む為に保つ）．tree-sitter-swift は前置の演算子を右に続く中置式の全体へ掛けて読む為（`-x - y` を `-(x - y)` と読む），Swift の前置の式は右の中置式の優先度で比べる（`y - (-x - y)` の括弧を保つ）．C / C++ で同優先度の二項式同士でも括弧が右被演算子（親の名前付子添字 ≥ 1）なら保持 (`a - (b - c)` ≠ `a - b - c`)．結合性を持たない演算子（Python・Rust・Swift の比較，Ruby の等価比較，PHP の大小・等価比較，Swift のシフト）は同優先度でも両側の括弧を保持する．TS は `X < Y > (Z)` を型引数付の呼出と読む為，`>` の右の被演算子が整形後に `(` 又は `` ` `` で始まる時だけ左の `X < Y` を包む括弧を保持する（`(a < b) > c` は同じ読みの `a < b > c` へ外す）．Go は `<<` `>>` `&` `&^` を乗除と同じ格，`|` `^` を加減と同じ格，比較を全て同じ格に置き，C 形式の表と乖離する為，Go 専用の格で判定する（`(a << 1) + b` は `a << 1 + b` と同じ結合で外れる）．Rust の `as` は前置単項より下・乗除より上の格（`(x as i32) + y` → `x as i32 + y`．型の後の `<` `<<` は型引数の始まりと読まれる為，其の前の変換を包む括弧は保つ）とし，累乗の右結合の扱いは `**` を持つ言語（Python・JS / TS・Ruby・PHP）に限る．TS / Swift の型の変換（`as`）が中置の演算子の左の被演算子の時は，型の後の演算子を型が取り込む（`<` `<<`，TS の `&` `|` `?`，Swift の `&` `?`）場合を除き，変換は右の型で閉じて演算子と結合を争わない為に優先順位に依らず外す（`(m as number) + n` → `m as number + n`，`(x as! Int) * 2` → `x as! Int * 2`．逆側に強い演算子が隣接する `x - (m as number) * 2` と，左に同じ格以上の演算子が隣接する `a < (m as number) + n`（外すと `(a < m as number) + n` と読まれる）は保つ．TS の `satisfies` も `as` と同じ格で扱い，Swift の `as?` も同じく外す（`(x as? Int) ?? 0` → `x as? Int ?? 0`）．C# は `as` の後の型の読みを確かめれない為，Kotlin の `as` は乗除より強い為に優先順位に委ねる）．反復の見出しの `in`（PHP の `foreach` は対象の後の `as`，C# の LINQ の `from` / `join` の `in` も含む）は演算子でない為，反復対象は代入・`yield` 等の最も弱い式も括弧無で取る最も弱い格 (1) で比べ（Python の内包の反復対象は三項・ラムダを取れない為に 3），代入の左辺・同じ格の結合の向きでは比べない（`for x in (a or b):` → `for x in a or b:`，`foreach (var x in (a ?? b))` → `foreach(var x in a ?? b)`，`foreach (($a ?: $b) as $v)` → `foreach($a ?: $b as $v)`，`from x in (a ?? b)` → `from x in a ?? b`．内包の `[x for x in (b if c else a)]` は保つ．`NodeKind::IterationHeader`）．範囲は結合性を持たない為（Kotlin の左結合の範囲も値の型が範囲の範囲に為り，ネストは書かれない），範囲同士の括弧は保つ（`(a..b)..c`）．Rust の範囲 `..` / `..=` は `||` より弱く代入より強い格 (3) で比べる（`for i in (0..n)` → `for i in 0..n`）．前置の単項（キャストを含む）の被演算子の前置の単項は結合を争わない為に外す（`(long)(-y)` → `(long)-y`．`- -y` の様な字句の融合は § 3.5 の空白の規則で防ぐ）．
8. **Ruby の字面に範囲が依存する式**：括弧無引数の呼出（`(f 1)`），及び閉じ括弧・カンマが続かない終端の無い範囲（`x = (1..)`．Rust / C# の `(0..)` も同じ）を包む括弧は保持．外すと後続の字句や次の行を引数・範囲の終端として取り込む（閉じ括弧・カンマが続く `a[(1..)]` / `m((1..))` と，Rust / C# の文の終わりの `;` が続く `let r = (0..);` は外す．Ruby の `;` は整形が改行へ置き換える為に保つ）．空白を挟まずに括弧が続く `not(a)` は呼出に似た一次式で後置・二項の演算子より強く結合する為（`not(a) == b` を外すと `not (a == b)`），実引数・代入の右辺の中（括弧無の `not a` は構文誤り）と共に保つ（空白を挟む `not (a)` と，文其の物の `not(a)` は外す）．`defined?(a)` も保つ．
9. **Swift の try / await と演算子記号の隣接**：`try` / `await` は右に続く中置式の全体へ掛かる為（`(try? f()) ?? 0` を外すと `try? (f() ?? 0)`），包む括弧は保持．Swift は演算子の前後の空白で前置・後置・中置を見分け，被演算子へ密着させる前置・後置・範囲の演算子と記号が並ぶと１つの演算子へ融合する又は空白の偏りで読みが変わる為（`(x!)!` が `x!!`，`-(-x)` が `--x`，`a..<(-1)` が `a..<-1`），内側の端と其の演算子が共に記号なら構文木の隣接で判定して保持する（原文の空白の有無に依らない）．単項の演算子と被演算子の間に空白を置けない為（`- -x` は構文誤り），他の言語の様に空白で区切る形にも出来ない．tree-sitter-swift は前置を右に続く中置式の全体へ掛けて読む為（`-(-x) - y` を `-((-x) - y)` と読む），左端を共有する祖先を遡って前置を探す．両側に空白を置く中置の演算子は隣の記号と融合しない為，外す（`y - (-1)` → `y - -1`）．但し文字列の補間（`"\(式)"`）の中は演算子の前後の空白を原文の儘に保つ為（§ 3.5.3），記号の演算子と内側の端の記号が接する括弧を保つ（`"\(a-(-b))"`）．

10. **C / C++ のマクロの実引数の端**：マクロ本体は実引数を字句の儘埋め込む為，全て大文字の呼出先（マクロの命名慣行）と同じファイルで定義した関数形式マクロ（本体が其の名前だけの別名 `#define t2 twice` を含む，`TSSource::CollectMacros` / `IsFunctionMacro`）の実引数では，実引数の左端・右端に接する括弧を保持する（`#define DIV(e) 100/e` の `DIV((a * b) + c)` は `100/(a * b) + c` に展開され，外すと `100/a * b + c`）．名前だけを包む括弧も，名前が全て大文字（マクロの命名慣行）なら別のファイルで式へ展開するマクロかも知れない為に保持する（`#define SUM a + b` の `(double)(SUM) / 2` を外すと `(double)a + b / 2`）．同じファイルで変数・仮引数・関数・列挙子として宣言した名前（`int f(int X)` の `(X)`）は宣言の位置でマクロでない為に外す．但し使う位置より前の最後の宣言と使う位置の間に取込の指令（`#include`）が有る名前（其の取込がマクロに定義し得る），前処理の条件の塊（`#if` / `#ifdef` / `#ifndef`）の中だけで宣言した名前（其の名前がマクロの時に読み飛ばされる枝かも知れない），同じファイルでマクロとして定義・取消・条件で問う名前（`#define K` / `#undef K` / `#ifndef K` / `defined(K)`）は宣言した名前に数えない（`TSSource::IsDeclaredName`）．`return` / `co_return` の値の全体を包む括弧（`return (MAX);` / `co_return (MAX);`）はマクロの展開後も括弧の有無で値が変わらない為，式へ展開するマクロを含んでも外す（`throw` の値は代入式の為，コンマへ展開すると `(throw 1), 2` と読まれて投げる値が変わる為に保つ）．
11. **Rust の値の無い脱出の式で終わる見出し**：見出しの右端（閉じの字句で終わらない最後の名前付の子を辿る）が値の無い `return` / `break` / `yield`（`RustValueJump`）の時は，括弧を外すと本体の塊を其の値として取り込む為に保持する（`while (return) {}`）．
12. **Swift の片側だけの範囲と前置の演算子の誤読**：片側だけの範囲（`..<n` / `n...`）は前置・後置の格で比べる（`arr[..<(n - 1)]` を保持）．範囲の演算子の直後の記号も融合する為に保持する（`0...(-x)` の `...-`）．tree-sitter-swift は前置の演算子の後の括弧（`-(y)` / `!(c)`）を演算子の呼出と読む為，名札の無い実引数１つの形は前置の被演算子を包む括弧として扱い，被演算子が前置より強く結合し記号で始まらなければ外す（`-(y)` → `-y`，`-(y + 1)` は保持）．
13. **Kotlin / Swift のラムダ**：ラムダ（`lambda_literal`）は文頭で括弧を外すと前の行の呼出の後置のラムダに読まれる為，`GreedyTailExpression` と同じく値の位置でだけ外す（`val c = ({ 1 })` → `val c = { 1 }`）．
14. **Swift の照合**：要素が１つの組の形の照合（`case (1):` / `if case (let v) = x`）は組でなく照合を包む冗長な括弧の為に外す．見出しの括弧の無い式の照合（`if case 1 = x`）は解析器が読めない為，見出しでは束縛（`let` / `var`）と列挙の場合（`.some(v)`）だけを外す．
15. **Python の組**：要素が１つでコンマの無い組の形（`for (i) in xs:`）は組でなく名前を包む冗長な括弧の為に外す．組を括弧無で置ける位置（戻値・`yield` の値・代入の両辺・`for` の対象と反復対象・内包の対象・`del` の対象・式文・添字の全体．`NodeKind::PythonBareTupleHost`）の組の括弧も冗長の為に外す（`return (a, b)` → `return a, b`，`(a, b) = x` → `a, b = x`，`x = (1,)` → `x = 1,`，`d[(a, b)]` → `d[a, b]`）．括弧の内側の端の空白も共に外す（行頭の組の空白が残るとインデントに加わり，後続の文が外側の区画へ移る）．行幅を超える時は行分割（§ 3.7）が括弧を付け直して要素の間で折り返す．実引数・要素・ラムダの本体・条件式等の中の組，`yield from` の値（組を置けない），セイウチ演算子・`yield` を要素に持つ組（括弧の無い組に置けない：`x = (y := 1, 2)`），星付の要素を含む添字の組（3.11 以降に限る）と `for` の反復対象の組（3.9 以降に限る），添字の値の側の組（`(a, b)[0]`）と他の要素と並ぶ添字の組（`d[(a, b), c]` / `d[(a, b),]`．外すと要素が添字へ分かれる），`return` / `yield` の値の星付の要素を持つ組（3.8 以降に限る），注釈付の代入の対象の名前を包む括弧（`(x): int = 1`．注釈を `__annotations__` へ記録しない印．ネストは外の層だけを残す）は保つ．組を包む括弧の層（`x = ((a, b))` / `for ((p, q)) in xs:`）は，外の位置で組の括弧も外せるかを判断し，外せれば共に外す．
16. **型の括弧**（`EditPass::MaybeCollectTypeParenEdit`）：名前等の原子の型を包む括弧（`(string)` / `(Int)?` / `(A)[]`）と，型の演算子の被演算子でない位置（注釈・別名・型引数・戻値の型・仮引数の型）の型を包む括弧は冗長の為に外す（TS / Kotlin / Go の `parenthesized_type`，Swift / Rust の要素１つの組の型）．型の演算子の被演算子に置いた演算子を持つ型（`TypeOperatorInner`：合併・交差・関数・条件・`keyof` 等）は外すと結合が変わる為に保つ（`(A | B)[]` / `(() => void) | null` / `(() -> Unit)?` / `&(dyn A + Send)` / `chan (<-chan int)`）．合併・交差は結合則を持ち，合併の被演算子の交差の型は合併より強く結合する為に外す（`A | (B & C)` → `A | B & C`）．TS の矢印関数の戻値の型の関数の型（`(): (() => void) => x`）と条件の型の比べる型の貪欲な型（関数・構築子・条件・`infer` の型）は後の `=>` `extends` と紛れ，照合の型の条件の型は置けない為に保つ（枝の型は何れも外す：`T extends A ? () => void : B`）．照合の型の中の関数の型の戻値の型の右端に制約付の `infer` が出る時は，関数の型を包む括弧を保つ（`T extends ((x: T) => infer R extends string) ? R : 0`．外すと `extends` の後が条件の型の始まりと読まれる．戻値の型を包む内側の括弧は外す）．関数の型の外の `T extends (infer U extends string) ? U : 0` は外す．`typeof` の型は後置の `[]` / `[K]` と `keyof` が其の型へ掛かる為に外す（`keyof (typeof x)` → `keyof typeof x`，`(typeof x)[number]` → `typeof x[number]`）．Swift の省略可能の型は印が型へ密着して結合を争わない為に何の被演算子でも外す（`(Int?)?` → `Int??`，`(Int?).Type` → `Int?.Type`）．Swift の関数の型の仮引数の並び（`(Int) -> Int`）は括弧が構文の為に，型の並びの展開を要素に持つ組（`(repeat each T)`）は組の為に対象外とする．Go の型の変換の型は名前・並び・構造体・インタフェースの型の時だけ外す（`(int)(x)` → `int(x)`，`(interface{})(x)` → `interface{}(x)`．`(*T)(x)` / `(func())(x)` は後の `(` と結合を争う為に保つ）．Go の `<-` は最も左の `chan` へ掛かる為，向きの無いチャネルの要素の受信専用のチャネル（`chan (<-chan int)`）の括弧だけを保ち，ポインタ・向きの有るチャネルの要素は外す（`*(chan int)` → `*chan int`，`chan<- (chan int)` → `chan<- chan int`）．

17. **型引数と読まれる比較**：TS・C#・C++ は一覧の要素の `a < b, c > (d)` を型引数付の呼出 `a<b, c>(d)` と読む事が有る為（TS・C# は `>` の後の字句で，C++ は `a` がテンプレートかで決まる），実引数・配列・初期化子の要素（`TypeArgumentLookalikeSlot`）で最上位（閉じる対の外）に `<` の比較を持ち，一覧の後の要素に `>` が在る括弧を保持する（`f((x && a < b), c > d)`．後に `>` の無い `g((a < b))` は外す）．tree-sitter-cpp / tree-sitter-c-sharp が比較とシフトを型引数と読み違えた中身（`(a < b, c >> d)` を `a<b, c>` と `> d` と読む）は，外すと最上位のコンマで実引数・宣言子が割れる為，読み違えた型引数の並び（閉じの `>` に `>` / `=` が続く物）の中にコンマを持つ括弧も保持する．
18. **C++ のテンプレートの山括弧の中の比較**：テンプレートの実引数・仮引数の既定値の中の `<` `>` は，括弧を外すと並びの開閉と読まれる為（`tf<(3 > 2)>(5)` が `tf < 3 > 2 > (5)`，`template <int N = (1 > 2)>` の `>` が並びの閉じ），他の対の括弧を挟まずに山括弧の並びへ届く括弧は保持する（最初の子が名前付の祖先（二項式・宣言等）は括弧の対を開かない為に更に上り，丸括弧・角括弧・波括弧の対で止める）．

値の位置（`ParenValueSlot`）には実引数（C# / PHP の `argument`・Kotlin の `value_argument` 等）・要素（PHP の `array_element_initializer` 等）・仮引数の既定値（JS / TS の `g = (() => 1)`・Python の `g=(lambda: 1)`・Kotlin の `g: T = ({ 1 })`・C++ の `F g = ([] {})`・PHP の `$g = (fn() => 1)`）・`export default`・`throw`・`yield`・三項の値（`c ? (x => x) : y` の `:` の前も区切りに数える）・C++26 の置換 `[: … :]` を含み，此処の貪欲な式は親の演算子と結合を争わない為，優先順位でも比べずに外す（`yield (x => x)` → `yield x => x`）．

符号で始まる内側（`-x` / `++x` / 符号付の数値等）も上記に該当しなければ外す．二項の演算子は両側に，語の単項の演算子（`not` / `typeof` / `void` 等）は後に空白を置く為，符号と融合しない（`y - (-1)` → `y - -1`，`typeof (-x)` → `typeof -x`）．記号の単項の演算子と内側の最初の記号が１字句へ融合する組（増減の演算子を持つ言語の `-(-x)` の `--` と `+(++x)` の `++`，論理積を字句に持つ言語の `&(&x)` の `&&`，Ruby の `!(~x)` の `!~`，Kotlin の `!(!c)` の `!!`．`EditPass::FusesPrefixOperator`）は括弧を保持し，括弧の無い原文（`- -x`）は被演算子を括弧で包む（符号は被演算子へ密着させる為，空白で区切る形にはしない）．増減の演算子を持たない Python / Ruby / Rust は融合しない為に外して密着させる（`-(-x)` → `--x`）．

括弧削除時は，左隣文字が英字なら `(` を削除ではなく `' '` に置換（`if(`→`if `等のトークン結合防止）．括弧の内側の端の空白と改行も共に剥がす（`return (` の後の改行が残ると JS / TS・Go・Kotlin は `return` で文を終えて値を返さない）．Kotlin は改行で文を終える為，括弧の直下の字句の間の改行も空白へ畳む（`(a` の次の行に `+ b)` を外すと `+ b` が別の文に為る）．鍵と値の対（`{ a: (x => x) }`）の `:` は演算子として扱わない．Ruby は名前の後の空白の後の記号を実引数と読む為，括弧を外した後の二項の演算子は前後を空白で離し（`(foo) -1` → `foo - 1`．演算子の前に空白が無い `(a)-b` は `a-b` の儘），三項の条件の括弧を外した後の `?` も前後を空白で離す（`(a)?b:c` → `a ? b : c`．`a?` の名前と読まれない）．内側の端と外の字句が共に演算子の記号なら，`(` / `)` を空白へ置き換えて記号の融合を防ぐ（`y-(-1)` が `y--1`，TS の `(a!)==b` が `a !== b` に為らない様にする．空白の後の整形で `y - -1` / `a! == b` に揃う）．

**省ける括弧の並び**（`EditPass::MaybeCollectOptionalParenEdit`）：言語が省く事を許す仮引数・実引数の括弧も冗長の為に外す．外の字と内側の端が共に語の字なら空白へ置き換える（`async(x) => x` → `async x => x`）．

- **名前だけのラムダの仮引数**：JS / TS の矢印関数の仮引数１つ（`(x) => x` → `x => x`．型・既定値・省略の印・残余・分割代入の仮引数と，型の仮引数・戻値の型を持つ矢印関数は保つ），Java の推論型の仮引数１つ（`(x) -> x`），C# の型の無い仮引数１つ（`(x) => x`．修飾 `async` / `static` だけなら外し，属性・戻値の型を持つ `[A] (x) => x` / `int (x) => x` は保つ），Swift のクロージャの名前だけの仮引数（`{ (x, y) in }` → `{ x, y in }`．型を持つ物は保つ），Ruby のラムダの名前だけの仮引数（`->(x, y) {}` → `-> x, y {}`．`&b` 等の記号付の仮引数は外すと読みが変わる為に保つ）．
- **空の仮引数**：C++ の修飾・戻値の型の無いラムダ（`[]() {}` → `[] {}`．`mutable` / `-> T` / `noexcept` 等を伴う物は C++23 より前は省けない為に保つ），Ruby のラムダ（`->() {}` → `-> {}`）と定義（`def f()` → `def f`．同じ行に本体が続く `def f() 1 end` は外すと本体を仮引数と読む為に改行で区切り，`def f()=1` は代入の名前 `f=` と読まれない様に空白で離す），Python の類の基底（`class A():` → `class A:`），Kotlin の類の主の構築子（`class A()` → `class A`．副の構築子は主の構築子へ委譲する為，副の構築子を持つ類は保つ）．
- **空の実引数**：後置のラムダ・クロージャだけを渡す呼出（Kotlin・Swift の `xs.map() { }` → `xs.map { }`．被呼出側が呼出の `f()() { }` は外すと後置のラムダが其の呼出へ移る為に保つ．Swift の連鎖の中の `xs.filter() { $0 }.count` も同じ），注釈・属性（Java・Kotlin の `@A()`，C# の `[A()]`，PHP の `#[A()]`．Kotlin の型の位置の注釈 `@Composable () -> Unit` は解析器が関数型の仮引数を注釈の実引数と読む為に保つ），列挙の定数（Java・Kotlin の `X()`），生成（JS / TS / PHP の `new A()` → `new A`，C# の初期化子を伴う `new A() { X = 1 }` → `new A { X = 1 }`．生成が後置の式の受け手の時（`new A().b` は外すと `new A.b` と読まれる），TS の比較の左辺（`new A < b > (c)` は型引数付の生成と読まれる）と TS の型引数を伴う生成（`new A<T>()`）は保つ），PHP の `exit()` / `die()`，SCSS の mixin（`@mixin m()` / `@include m()`．`@function f()` の括弧は Sass が要する為に保つ），Ruby の受け手の有るメソッドの呼出と `yield`（`a.b()` → `a.b`，`yield()` → `yield`．受け手の無い名前は局所変数と読まれ得る為に `?` `!` で終わる名前だけを外し，`::` の後の定数の名前は定数の参照と読まれる為に保つ．名前の後の空白の後の記号を Ruby は実引数と読む為，添字・参照の記号は名前へ密着させ（`a.c() [1]` → `a.c[1]`），演算子は後にも空白を置いて二項の演算子と読ませる：`a.b() -1` → `a.b - 1`）．

#### 3.4.2 冗長ブレース除去 (`{ stmt }` → `stmt`)

`if` / `else` / `for` / `while` / `do` と Kotlin の when の枝（`1 -> { foo() }` → `1 -> foo()`．本体の if 式の後続の枝は枝の中で閉じる為，else の枝と同じく包まない）の単一文本体の `{ ... }` 除去は，`ApplyConsolidated` の後，構造化（§ 3.5）の前に `EditPass::ApplyBraceEdits` が固定点反復として実行する．行幅に依らない編集の為，構造化の前に済ませて除去後の本体も構造化の空白・改行規則で組み直す（構造化の後に除去すると，閉じ波括弧の跡の改行や本体の前の空白が残り，次の巡で初めて整う）．行幅超過のブレース付与（§ 3.7）より前に完結する為，「付与 → 再除去」の振動も起きない．付与と除去の判定が食い違う不具合で以前の本文へ戻った場合は，巡りを打ち切り構文守衛と同じく原文を保つ．else 節を持たない文法（Java / C#）の else の本体も，else 節を持つ文法と同じく除去する．

宣言本体には，元の波括弧の有無や行幅に依らず波括弧を付ける（ラベルの付いた宣言 `lbl: function f() {}` / `L: int x = 1;` は包むと有効範囲と巻上げが塊の中へ閉じる為に包まない）．`else` の枝以外の本体に置いた `else` を持つ `if`（宙ぶらりんの `else`）と，本体の do-while は，本体自身が複数行に渡る為に包む（`if(a) { if(b) x();`<br>`else y(); }`，`while(c) { do x();`<br>`while(a); }`，後に外側の `else` が続けば `} else z();`）．`else` の枝の手前の本体が波括弧の中の開いた `if` で終わる形（`if(a) for(;;) { if(b) x(); } else y();`）は，内側と外側の何方の波括弧で守るかが外す順で変わる為，外側の本体を包み（`if(a) { for(;;) if(b) x(); } else y();`），内側の単文の波括弧は外す．`else` の枝の本体の `if` は波括弧を外して `else if` の連鎖に揃える．ラベルの付いた文（`L: if(b) x(); else y();`）はラベルの後の文で判定する．tree-sitter-php は波括弧の無い本体が開いた `if` で終わる時に後続の枝を外側の `if` へ結び付けるが，PHP は内側の `if` へ結ぶ為，本体と枝を波括弧で包んで読みを PHP へ一致させる．構文木で更に外側の `if` に属する枝も PHP では本体の中の `if` へ結ぶ事が有る為（`if(a) if(b) if(c) x(); else if(d) if(e) y(); else z(); elseif(f) w();` の `elseif(f)` は `if(d)` に属する），包む範囲は PHP の読み（後続の枝は其の手前で開いた儘の最も内側の `if` へ結ぶ）を模して求め，最も外側の包みから適用する（誤った結付の構文木では他の編集の範囲も誤る為，此の修正が有る反復では其れだけを適用する）．

除去対象は C / C++ / C# / Java / Kotlin / PHP / JS / TS．以下の場合は保持（何れも AST の形だけで決まり，コメントの有無では変わらない）．

- 本体が空，又は宣言．
- ラムダ又は後続演算の結合が変わる本体．
- 本体の直後に if の後続の枝（`else` / `elseif`）が続き（本体で終わる祖先の後続を含み，間の前処理指令の行 `#if` 等は読み飛ばす），本体が else を持たない `if` で終わる文（`while` / `for` / ラベルの本体を辿る．外すと後続の枝が内側の `if` へ結び付き直す：`if(a) while(c) { if(b) y(); } else z();`）．
- 本体が PHP の地の文（`{ ?>X<?php }`）：`?>` は文の終端として働き，外すと `if(c);` と無条件の出力に分かれる．
- 本体が TS の `using` / `await using` 宣言：解析器は代入式と読むが宣言の為，単文の本体に置けない．
- 本体が値を使う Kotlin の if 式・when の枝の代入・繰返（`val y = if(a) { x = 1 } else 2` / `val v = if(c) { for(i in r) g() } else 0`）：外すと式の位置に式でない文が来る（値を使うかは `EditPass::IsKotlinStatementValueUsed`．文として置いた if 式・when の枝の代入・繰返は外す：`2 -> x = 3`）．

**JS / TS の ASI 対策**：末尾 `;` 不在の `{ stmt }` は `}` を `;\n` に，`{` を空白に置換する．`if(c) X = Y else Z = W` 化で `else` が孤立する事故を防ぐ．Kotlin の if 式の後続の `else` の前の `}` は空白に置換する（改行にすると tree-sitter-kotlin が when の枝の中で次の行の `else "o"` を枝と読み違える．else の前の改行は構造化が決める）．

### 3.5 `NormalizeStructured` / `NormalizeInlineSpaces`

#### 3.5.1 `NormalizeStructured`

**対象**：C / C++ / C# / Java / Go / Rust / Kotlin / Swift / PHP / JS / TS / Ruby / JSON / HTML / CSS

AST からソースを完全再構築する．[`StructurePass::BuildStructuredText`](../src/Pass/Structure.cpp) をルートの最上位子毎に並列実行する（スレッド毎の `FlatCache` / `StructuredCache` / `ContainsCache`）．各子は平坦（１行）又は構造化（多行）何方に展開するかを以下で決定．

- **展開要件**：

	1. インデントブロック系ノード（`statement_block` 等）が名前付子を持つ．Ruby の波括弧のブロックは本体が１文なら１行に置く（`f { |i| i * 2 }`）為，本体が２文以上の時だけ展開要因とし，ラムダ（`-> { 1 }`）は本体のブロックで決める（１行のブロックを含む実引数を展開しない：`puts(items.map { |i| i * 2 }.sum)`）．
	2. JSX 要素／断片が子コンテンツを２個以上持つ（タグ・空の式・空白のみの本文は除外し，連続する本文と文字参照は１個と数える）．
	3. do-while，又は `else` を持つ Kotlin の `if` 式．但し `->` の後の値の if 式（when の枝の本体・ラムダの本体の唯一の文．else if の連鎖の内側の if 式は連鎖の最も外の if 式で判定する）は，else を次の行へ置くと tree-sitter-kotlin が `else "b"` を when の枝と読み違える為に展開要因とせず，then の枝の冗長な波括弧を外した後も else の前で改行しない（`StructurePass::IsKotlinArrowBody`．構文木で判定し，`->` の後の改行の有無に依らない）．
	4. HTML 要素が子に要素を２個以上持ち，子の間に空白を置ける境界（下記「HTML の空白」）を持つ．
	5. 子孫に上記を含む（伝播）．

- **オブジェクトリテラル**：`ObjectLike` の値の列は其れ自身だけでは展開せず，子孫に展開要因が有る場合に展開する．Java の enum の本体は，本体の宣言部（`;` の後の成員）を持てば型の本体と同じく展開し，成員を行毎に置き，列挙子の並びを閉じる `;` を最後の列挙子へ密着させる（`B(2);` の次の行を空けて成員）．
- **実引数の並び**：展開要因を子孫に持つ実引数の並び・括弧（`ExpandContainer`：`argument_list` / `arguments` / Kotlin・Swift の `value_arguments` / `parenthesized_expression` 等）は要素毎に行を分けて展開する（`g({ 1 })` は `g(` の後に要素の行を置き `)` で閉じる．`StructurePass::BuildExpandedContainer`）．
- **PHP の地の文**：最初の開始タグより前（構文木の外の先頭の空白・空行を含む）と，`?>` から次の開始タグ迄（`text_interpolation`）は出力其の物の為，改行・インデント・行末空白を含め逐語で保つ（インデント・行分割・行末空白除去・空行の挿入の何れも掛けない）．末尾が地の文のファイルは末尾の改行の数も保つ．地の文の境界では，最初の開始タグを地の文へ直に続け，開始タグの後は次の閉じタグ迄が１文なら同じ行へ続け（`<?php endif; ?>` / `<?= $x; ?>`），２文以上なら改行する（値を出力する `<?=` はファイルの先頭でも同じ）．閉じタグの前は直前の開始タグ以降が１行に収まれば同じ行へ続ける．
- **PHP の閉じタグが終える文**：`?>` は直前の文を終える `;` として働く為，省かれた `;` を明示する（規約 2.15．`<?= $x ?>` → `<?= $x; ?>`，`endif ?>` → `endif; ?>`）．式で終わる文は末尾の式が `}` で終わっても `;` を補い（`$f = function() {} ?>`），本体・宣言の `}` や見出しの `:` で終わる文には補わない．制御構文（`if` / `elseif` / `else` / `for` / `foreach` / `while`）の見出しの直後の `?>` は本体を空にし，後続の地の文と文は無条件に実行される（`while($a) ?>X<?php f();`）．tree-sitter-php は後続の文を本体と読むか本体の無い文と読む為，見出しの後の `;` の明示（`while($a); ?>X<?php f();`）で読みも PHP へ一致させる．
- **実行されないデータ**：Ruby の `__END__` 以降（`DATA` が読む）と PHP の `__halt_compiler();` / `__halt_compiler() ?>` の後（`__COMPILER_HALT_OFFSET__` の位置から読む）はコードでない為，インデント・行末空白・末尾の改行の数を変えない．PHP は構文解析器がデータをコードとして読む為，データを切り離して手前のコードだけを整形する．改行様式は原本全体で判定し，ファイルへの書戻では元の様式へ戻す．標準入力では他の箇所と同じく LF へ統一する．
- **PHP の代替構文**：本体を開く `:`（`colon_block` / `switch_block` の先頭，`for` / `declare` の直下）は見出しへ密着させ，本体の文を行毎に置き，本体の後の節（`elseif(...):` / `else:`）と終端語（`endif;` 等）は行頭に置く（地の文の直後は同じ行．本体の文が無ければ `:` の後の同じ行：`foreach($a as $b): endforeach;`．空の本体の `colon_block` を持たない `for` / `declare` も同じ：`for(...): endfor;`）．インデントは `:` から後続の字句迄を仮想の括弧対として１段深くする．
- **前処理指令**：字句の区切りは空白の有無だけが意味を持つ為，空白の並びを１つへ畳み，指令名の前の空白（`#  define`）を詰める．文字列・文字・コメント・取込経路（`#include <a b.h>`）の内側は保つ．マクロ名と `(` の間の空白の有無（関数形式か否か）は変えない．
- **文として並ぶ無名の字句**：文の区切り `;` 以外の無名の子も文其の物として残す（Swift の暗黙の戻値 `case 1: nil` / `if c { nil }` の `nil`）．
- **Swift のコンパイラ指示子**：行単位の構文の為，後続を必ず次行へ送る．連鎖中の `#if`（`x.map { }` + `#if DEBUG` + `.filter { }` + `#endif` + `.count`）は解析器が指示子を連鎖の受け手と読むが，指示子の後を改行すれば元の連鎖に戻る．
- **隠れ字句**：C# の修飾子付暗黙型ラムダ仮引数を開く `(`（`(ref x) => x`）は文法が子に出さず子の間の原文にだけ残る為，補って仮引数へ密着させる．
- **文の区切り**：Kotlin・Swift は改行の後の `{` を前の文の末尾ラムダとして読み，tree-sitter-kotlin は改行の後の `(` `[` `::` も前の式の呼出・添字・参照へ繋ぐ為，其れ等で始まる文の前を `;` で区切る．Kotlin は改行で文を終える為，tree-sitter-kotlin が改行を跨いで前の式へ繋いだ呼出・添字・参照（`g()` の次の行の `(0..3).forEach`・`x` や `f()` の次の行の `::g`）は，統合編集より前の単独の巡 (`EditPass::ApplyKotlinJoints`) が継ぎ目の前へ `;` を補って別の文として読み直させる（誤って繋いだ木の上で括弧除去等を判断すると，区切った後の巡で結果が変わる）．JS / TS のクラスの本体で改行の後に置いた値の無い欄 `get` / `set` / `static`（`static` の次の行の `x = 1`）は後続の成員の修飾と読まれるが，tree-sitter は欄と読む為，同じ巡 (`EditPass::ApplyJsJoints`) が改行を空白へ畳んで読みを揃える．改行で切れる `abstract` / `accessor` は逆に欄の名前として区切る（`"accessor";`．名前の欄は解析器が修飾と読む為，字句の名前にする）．其れ以外の行末の `;` は復元しない（規約 2.15）．解析に失敗した部分（`ERROR`）の隣は原文の間隙を写し，構造化で落ちた前の文の区切り `;` も戻す．Ruby のヒアドキュメントの本文は開始の行の次行から始まる為，本文を控えた開始の後の文（`puts <<~EOS; return 1`）は同じ行へ `;` で続ける．Rust は波括弧で終わる式文の終端 `;` を空文として分ける為，前の文へ密着させる（`match x { ... };`）．
- **Ruby の文の並び**：文の区切りの改行は字句に現れず，空白で繋ぐと文が繋がって実引数等に読まれる為，平坦化では `;` で区切り（`(a; b)` / `BEGIN { a; b }`），展開では文毎に改行する（`NodeKind::RubyStatementSequence`）．
- **Ruby の分岐の節**：`if` / `unless` / `case` は，複数文本体の節だけを見出しの次行へ展開し，単一文本体の節は次の節境界迄を１行に置く．全節が単一文なら１行に畳み（`if c then a else b end`），実引数・配列等も要素が全て１行なら展開しない（`p(if a then 1 else 2 end)`）．畳んだ分岐が幅を超える時は，行分割（§ 3.7）が単一文本体を保って節境界で改行する．
- **Ruby のヒアドキュメント**：本文は開始の在る行の次行から始まる為，本文がノードの外に続く開始の後では，節・`end` を開始と同じ行に保つ（`in <<~X then end`）．開始と本文の数は部分木毎に足し引きし，前の兄弟の開始の本文を含む子（`if <<~A then` の `then`）では減らす．見出しの後に本文が並ぶ構文は全体を多行に置く．見出しが終端の無い範囲で終わる節（`when 1..`）は，改行が範囲の続きに読まれる為，多行でも ` then` で閉じる．ブロックの子として現れる本文（`foo(<<~X) do |y|` の後）も前後で改行する．
- **HTML の空白**：子の境界（開始タグの直後・終了タグの直前を含む）の空白は，要素の既定の表示形式（HTML 仕様の描画の章）で描画の有無が決まる．

	- 行を区切る子（`<div>` / `<p>` / `<li>` / 表の部品等，`NodeKind::HtmlBlockTag`）の前後と，行を区切る要素・文書の根の内側の端は，空白が行頭・行末に当たり描画されない．展開時は改行を置き，平坦時は詰める．
	- 其れ以外（行内の要素・本文・文字参照の間と，行内の要素の内側の端）の空白は１個の空白として描画される為，有無を保つ．空白が有れば展開時は改行，平坦時は空白１個とし，無ければ密着させる（改行を置くと空白が描画され，詰めると語が繋がる）．
	- 箱を作らない子（`<script>` / `<style>` / `<meta>` 等，`NodeKind::HtmlHiddenTag`，及びコメント）の前後の空白は隣の空白と合わせて描画される為，箱を作らない子を越えた先の子で判定する．
	- 終了タグの無い要素（空要素・暗黙に閉じる要素）は，構文解析器が後続の本文を子に取り込む為，後ろ側の境界は取り込んだ最後の子，前側の境界は自身が箱を作らなければ取り込んだ最初の子で判定する（`a\n<meta>b` の空白は `a` と `b` の間に描画される）．
	- SVG の図形・MathML の式の並びは子の間の空白を描画しない為，行を区切る子と同じく扱う．SVG の文字・MathML の字句の内側は行内と同じく扱う．
	- 空白・タブ・改行以外の文字（垂直タブ・改頁等，構文解析器が本文から外す物）を含む間隙は内容其の物の為，原文の儘保つ．
	- 本文（`text` 節点）の内側の空白・改行は文書の内容として其の儘保ち，インデントだけを付け直す．
	- 空白を描画する要素（`<pre>` / `<listing>` と `xml:space="preserve"` の明示）は子の間の空白と本文を原文の儘保ち，内側のタグだけを整える．内容を文字として読む要素（`<textarea>` / `<title>` 等）は開始・終了タグの間を原文の儘保つ．何れも内容の行へインデントを付けず，行末空白も除かない（§ 3.9 / § 3.10）．

トークン間スペースは `StructurePass::NeedsGapBetween` が決定する．§ 3.5.3 参照．

構造化の前後で Ruby の式の接続（呼出・添字・二項・単項の節点と其の親の並び，`StructurePass::RubyExpressionShape`）と Go の自動セミコロン挿入の不正改行（`StructurePass::HasBrokenGoContinuation`）を検査し，変われば § 3.11 と同じく原文へ差し戻す．発火は不具合として扱う．

#### 3.5.2 `NormalizeInlineSpaces`

**対象**：Python

構造再構築は行わず，行内の隣接トークン間スペースのみを `NeedsGapBetween` で正規化する．改行を跨ぐ空白は変更しない（インデント／意味的改行を保持）．

#### 3.5.3 `NeedsGapBetween`（隣接トークン間スペース決定）

`NeedsGapBetween(Parent, Cur, Next)` が以下のロジックで bool（スペース有／無）を返す．

優先度の高い言語特有ルール → カテゴリベースの汎用ルールの順で適用．主要ルール：

- **密着系（スペース無）**：`(` / `[` の内側，`.` / `->` / `::` / `?.` / `..` / `...` の前後，`,` / `;` の前，関数呼出 `f(x)` の `f` と `(`，添字 `a[i]` の `a` と `[`，キャスト `(int)x` の `)` と `x`，JSX タグ内属性の `=` 前後，テンプレート `${...}` の `${` / `}` 境界．
- **空白系**：二項演算子（`+` / `-` / `*` / `==` / `&&` 等）の前後，識別子と識別子間，`,` / `;` の後，非空の `{ ... }` の内側（JSX 式を除く），制御構文の見出しの `)` と `(` / `[` で始まる本体の間（`for(i = 0; i < n; ++i) (void)p;`），for-of の `of` と `(` の間（`for(const x of (a, b))`）．
- **言語固有**：

	- Ruby `&:foo` `block_argument` の `&` と次トークンは密着．
	- Ruby `%w(foo bar)` `%i(:a :b)` 等配列リテラルは区切り内側密着．
	- Ruby `:"#{x}=", '...', "..."` 等 `delimited_symbol` / `string` / `bare_string` / `bare_symbol` 内側は子境界密着（補間と `string_content` の間に空白を挿入しない）．
	- Swift `var x: Foo!` の IUO `!` は前名前付型と密着．左の字へ空白無で接する `?` `!` で始まる演算子は後置の演算子（任意の連鎖 `zs??.first`・強制の開封 `zs!!.first`，`x!=y` は `x! = y`）の為，解析器が利用者定義の演算子と読んだ１字の `!` / `?` で始まる物（`x!+1` / `x!=y`）は，其の字を後置の演算子として切り離して読み直させ（`x! + 1` / `x! = y`．`EditPass::ApplySwiftMisreads`．２字以上の並びの `x!!+1` は切り離しても解析器が `!!` を中置の演算子と読む為に原文の儘），演算子へ密着したコメント（`y +/* c */1`．解析器はコメントの始まりの２字を演算子の字と読み，コメントの中を式と読む）はコメントの前に空白を置いて読み直させ（`y + /* c */ 1`．Swift は演算子の字の並びをコメントの始まりで終え，コメントを空白と看做す為に意味は変わらない．読違の後ろの読みは当てに為らない為，最初の１つを直して局所の解析器で増分に読み直す事を繰り返す），`??` の nil 合体と読んだ物（`zs??.first`）は前後の原文の隣接を保つ（空白を入れると値・型が変わる）．文字列の補間の中の演算子の前後の空白も原文の儘に保つ（上の `!` / `?` の切離は読直の為に補間の中でも行う：`"\(x!+1)"` → `"\(x! + 1)"`．意味は同じ）．`as!` / `as?` と `[` で始まる型（配列・辞書の型）の間は空白で区切る（`x as! [Int: Int]`）．
	- Swift `case let .foo(x)` の `let` と `.` 間はスペース．
	- 修飾子・属性・生存期間・語等に続く `(` 始まりの型（組型・関数型・DNF 型等）は空白で区切る（`suspend () -> Unit` / `@escaping (Int) -> Void` / `public (int, int) M()` / `public (A&B)|null $p` / `&'a (i32, i32)` / `*const (u8, u8)`）．密着させると注釈の実引数や関数呼出と読まれる．
	- C / C++ の型と `(` で始まる宣言子は空白で区切る（`int (*p);` / `int (*f)(int) = 0;`．密着させると関数形式のキャストの字面に為る）．
	- Go の構造体・インタフェースの型は，空の本体を語へ密着させ（`struct{}` / `interface{}`），成員を持つ本体は展開する為に空白で区切る（`struct {` / `interface {`）．複合リテラルの型と値の `{` は密着させる（`struct{}{}`，`[...]int{ 1 }`）．
	- 名前付の節点に為る Swift の語（`let` / `var` / `where`）と `(` は空白で区切る（`case let (a, b)` / `where (c)`）．
	- PHP の参照渡し `&` は続く変数・可変長記号・関数名へ密着（`&$x` / `&...$x` / `function &f()`）．
	- Go の関数リテラル・関数型・インタフェースのメソッドの戻値の組は `)` の後を空白で区切る（`func(int) (int, error)`）．
	- Kotlin の上位型指定 `super<A>` / `super<A>@O` の記号は密着．型の位置の注釈と `(` の間は原ソースの隣接を保つ（§ 1.1）．
	- Rust の開始の無い閉区間を tree-sitter が `..` と `=` へ割って読んだ代入式（`&[..=..]`）は，`=` の前後を密着させて元の `..=` を保つ．範囲演算子同士（`.. ..`）は空白で区切る（密着させると `...` `.` と読まれる）．
	- JS / TS のタグ付テンプレートのテンプレートはタグへ密着（`` tag`t` ``）．Ruby のラムダの `->` と仮引数の並びの `(` は密着（`->(&b) {}`）．
	- C# の修飾子付暗黙型ラムダ仮引数の `)` は仮引数へ密着．C# のラムダの仮引数の並びの前は名前でなく修飾・戻値の型・属性の為，空白で区切る（`async (x, y) => x` / `int (x) => x` / `[A] (x) => x`．密着させると呼出・添字と読める）．
	- Ruby のブロック仮引数を閉じる `|` の前のカンマは詰める（`|a,|`）．`next` / `break` / `yield` 等の配列の実引数（`next [a, b]`）は空白で区切る（密着させると添字と読まれる）．
	- JSX の子の境界は密着させる．描画される空白は本文 (`jsx_text`) として節点に現れ，節点の間に残る改行を含む空白は描画されない．
	- 制御構文の見出しを丸括弧で包まない言語（Go / Rust / Swift / Python / Ruby）では，見出しに残る括弧（複合リテラル・値の無い `return` を含む見出し等）と角括弧で始まる条件・対象は式の一部の為，語との間に空白を置く（`while (return) {}` / `if (T{ x: 1 }) == a {` / `for range (T{}.xs) {}` / `for [a, b] in c:` / `if [a].is_empty() {}`）．
	- C# の分解の宣言の `var` と組の形は空白で区切る（`var (m, n) = t`）．
	- C# の `out` の無い実引数の `d * a` は，tree-sitter-c-sharp が `d*` 型の宣言式と読むが，宣言式を置ける実引数は `out` の物と分解の代入の左辺の組だけの為，乗算として `*` の両側に空白を置く（`StructurePass::ReadsAsCsProduct`）．
	- HTML の要素の子の境界は § 3.5.1「HTML の空白」の区分で決める．
	- tree-sitter-cpp / tree-sitter-c-sharp が比較とシフトを型引数の並びと読み違えた形（C++ の `b < c && d >= e` / `i < n >> 1`，C# の `a < b, c >> d`．型引数の並びが二項式を直に持つか，閉じの `>` に割れた `>` `=` が続く物：`StructurePass::IsMisparsedTemplate`）は，本来の比較演算子として `<` の前後と並びの内側に空白を置き（コンマの前は密着），割れた `>>` / `>=` は元の１字句へ密着させ，並びの後の実引数の並び（`c > (d + 1)` を `c>(d + 1)` の呼出と読む）の前にも空白を置く．

詳細は [`src/Pass/Structure.cpp`](../src/Pass/Structure.cpp) の `NeedsGapBetween` 実装を直接参照．分類用集合は [`src/Util/NodeKind.cpp`](../src/Util/NodeKind.cpp) で定義する．

### 3.6 `ApplyVarDeclMerge`

`ResumeAttachments` 後，紐付の再束縛済の段階で宣言編集を収集して適用する．

#### 3.6.1 `VarDeclMerge`（連続宣言統合）

**対象**：`IsBraceLang()` の内で統合する宣言の節点（`NodeKind::DeclLike`）を持つ C / C++ / C# / Java / JS / TS（PHP・Go・Rust・Kotlin・Swift は１つの宣言に宣言子を並べる此の形の節点を持たない）

連続する**同型・関数ローカル**の変数宣言を１つにマージする（関数引数は対象外）．C# の修飾子（`private` / `static` / `const`）と属性（`[Obsolete]`）は宣言子の並びの前に並ぶ型の頭の一部とし，同じ字面の物を統合し，分割では各宣言へ複写する（属性は複数の宣言子の欄の全てに掛かる為に意味は同じ）．

```c
// 整形前
int A = 1;
int B = 2;
int C = 3;
// 整形後
int A = 1, B = 2, C = 3;
```

関数ローカルは本工程では行長を制限せず１文へ統合し，幅超過の分割は後段の `SplitWideVarDecls` で行う．構造化で複数行に為る宣言（関数式・ラムダの本体等を含む）は統合の群に入れない．クラス様本体と最上位の宣言は統合対象外とし，複数宣言子を含む場合は `RunVarDeclSplitAndRemerge` で１宣言ずつへ分離する．関数ローカルでも複数宣言子を持つ複数行の宣言は同じく分離し，単一行の宣言子を前後の宣言と統合し直す（原文の宣言の区切りに依らず，１宣言子ずつ書いた場合と同じ形に揃える）．対象言語では分離後に不変修飾を付与し直し，内部の関数ローカル宣言を再統合する．付随コメントは統合・分割後のバイト位置へ再束縛する（宣言子のコメントは宣言子の前．分割で新しい宣言の最初に来た宣言子のコメントの内，原文で独立した行に在った物（`CommentAttach::IsStandalone`）は新しい宣言の前へ置き，`int /** D */ d = 2;` の様に型と名前の間へ入れない．Java 等の文書化コメントは宣言の前でしか宣言に付かず，統合と幅の分割を経る次の巡でも同じ所へ戻る．`SplitWideVarDecls` も同じ．宣言子の中のコメントは宣言の全体を宣言子の範囲の並びで１度だけ巡って集める．型の頭の中のコメント（`const /* c */ int`）は，分割では最初の宣言の型の頭へ，統合では統合した型の頭の同じ位置へ置く）．Java の enum の本体の宣言部（`;` の後の成員）もクラス様本体と同じく統合対象外とする．

### 3.7 `LineSplit`

**対象**：C / C++ / C# / Java / Go / Rust / Kotlin / Swift / PHP / JS / TS / Ruby / Python / JSON

`!MaxChars`（無制限）では幅超過に依る分割・括弧付与を省略する．Python も括弧外を含む候補を後行順で評価し，採用位置に必要な継続括弧を補って折り返す（代入の左辺と `for` の対象の括弧の無い組 `a, b = f()` と `del` の対象 `del a, b` も包む）．冗長ブレース除去は構造化の前に済ませて居る（§ 3.4.2）．以下を順に実行する．詳細は [`line_split_order.md`](line_split_order.md) 参照．

1. **`SplitWideVarDecls`**: 統合変数宣言が `MaxChars` 超過なら別宣言へグリーディ分割（汎用分割機構より前に確定させ，カンマ継続分割を抑止）．分割は兄弟の文を足せる親（`NodeKind::SplittableDeclParent`）の直下に限り，波括弧の無い C++ の `extern "C" int a, b;` は分けた宣言子が C の結合を失う為に分けない（`extern "C" { … }` の中は分ける）．
2. **`ApplyBraceWraps`（固定点反復）**：
	- **段階１**：`CollectBreaksParallel`（ルートの名前付子毎に並列，１回目の反復のみ実行）で分割可能無名トークン位置を収集．`GreedyMerge` でグループ単位の除去→行幅判定→復元を行う．文字数は `TextEdit::ContentChars` で UTF-8 符号位置を１文字としてカウント（制御文字は 0）．
	- **段階２**：`FindCtrlFlowsParallel` で行幅超過の単一文本体を持つ制御構文を検出し，最内側のみを対象とする絞込で `{ ... }` 付与対象を確定（`else` の直後の本体の if は else if の連鎖として包まず，`else` の無い if の本体の if（`if(a) if(b) g();`）は包む．Swift の `else` は名前付の葉の為，名前の有無に依らず字句の種別で見る）．除外する範囲（本体の中の文ブロック）は，文ブロックの範囲の一覧を巡毎に１度集めて二分探索で引き，除外範囲の中の分割・改行は範囲の終わりへ跳んで飛ばす（制御構文毎に部分木を辿るとネストの深さの三乗の時間に為る）．１行に畳んだ Kotlin の if の連鎖（when の枝・ラムダの本体の else を持つ if 式．構造化は `->` の後の if 式を展開しない）は，何れかの枝を包む巡に全ての枝の本体を包む（`CtrlFlowInfo::Chain`．１つの枝だけを包むと `… else if(a == 3) {` の次の行に本体，其の後の行に `} else if(a == 4) … else …` と連鎖の形が崩れる）．本体の外側に分割が無く見出し（条件）でだけ改行が要る制御構文は，見出しを `if(Cond) {` の１行に保てるなら波括弧を付けて本体を次行へ送る．見出し自体が行幅に収まらず条件を割る時は，本体を行頭に置いた条件の閉じ括弧へ続けて `) Body;` と同じ行に置き，其の行も行幅を超える時に限り波括弧を付ける．`TextEdit::Apply` 経由で `ts_tree_edit` を発行し，次反復の再構文解析を増分構文解析化する．`BraceLocks` は付与後の座標へ位置補正する．固定点（`NeedWrapSet` 集合が空）迄反復．２回目以降の反復では `Entries` を増分更新する．Ruby は `do...end` / `then...end` 形式で `{}` ブレース付与が適用不能な為，`FindCtrlFlows` 段階で対象外とする．
3. **`BreakWideRubyBranches`**（Ruby）: 構造化が１行に畳んだ分岐を段階１の分割が割るか，分岐を含む行が `MaxChars` を超える時，`then` と単一文本体を保って後続の節境界で改行し，`ApplyBraceWraps` をやり直す．収まる分岐は１行の儘とする．
4. **閉じの境界**：幅に依って初めて展開された波括弧の対の閉じの前で割り，中身（開きタグの属性・子）を割った JSX の要素は開きタグの後と閉じタグの前でも割って子と閉じタグを独立の行に置く（開き括弧の後でも改行し閉じ括弧の行で閉じる．行端の扱いが処理系で分かれる本文を持つ要素は除く）．
5. **`CollectElseWhileJoins`**: `}` の後に空白・改行（空行を含む）だけを挟んで `else` / `while(...);` が続く位置を構文木から集める（Ruby の節は波括弧で閉じず，`}` は枝の本体の値の閉じの為に集めない）．コメントは前段で分離済の為，判断には現れない．`while` は構文木で do-while（`do_statement` / Kotlin の `do_while_statement`）の字句と確かめた物だけを対象とし，本体の無い独立の `while(b);` は do-while と読み違える配置にしない．
6. **`BuildResult`**: 分割位置に改行を挿入し，括弧ペアの区間横断解析でインデント深さを決定（最終インデントは § 3.9 で再計算する為，本関数はタブを付与しない）．前項で集めた `}` で終わる断片の次は，改行でなく空白で続けて `} else` / `} while(...);` の形にする（間の空行は読み飛ばす）．
7. **式の接続の検査**：§ 3.5.1 と同じく，行分割の前後で Ruby の式の接続と Go の自動セミコロン挿入を比べ，変われば原文へ差し戻す（発火は不具合）．

行の幅は `BuildResult` が前の行の `}` へ続ける `else` / `while` の行では，結合後の `} ` を含めて測る．初期化の文を持つ見出し（`for(int i = 0; …)` / C++ の `if(auto x = f(); …)`．`NodeKind::InitHeader`）の子の文の終わりの `;` は，子の文の組から見出しの組へ移し，見出しを割る時に `;` 毎に揃えて割る（子の文の組に残すと，子の文が収まる時に `;` の後で割らず，其の間に決める内側の組が行の境を見失って `!x` と `.empty()` の間で割る）．TS は `X < Y >` の直後の改行で `>` を型引数の閉じと読み，次の行を別の文にする為（`a < b >` の次の行の `c` は `a<b>;` と `c;`），`<` の比較を左の被演算子に持つ `>` の後では割らない．JSX のタグは属性の前と，属性の後の閉じ（`>` / `/>`）の前で割り，属性の無いタグ（`<p>` / `<br />`）は割らない．行端の扱いが処理系で分かれる本文を持つ JSX の要素（§ 3.3）は，開きタグの `>` の後で割らない．節点の末尾に在る演算子（解析器が Swift の `x + -(y)` を `(x + -)` の呼出と読む前置の `-` 等）の後では，被演算子が節点の外に続き割ると離れる為に割らない（Swift は被演算子から離れた単項の演算子を読めない）．空の括弧の対（`()` / `[]` / `{}`．Java の注釈型の要素 `int[] v() default {};` は仮引数の並びの節点を持たず括弧が要素の直下に並ぶ）の内側では割らない（割っても行は縮まず，`v(` と `)` が別の行に分かれる）．Swift の左の字へ密着する後置の `?` `!`（§ 3.5.3）と省略可能の型の印 `?` の後，制御構文の見出しの束縛の `=`（`if let a = f(), let b = g {`．条件の区切りの `,` と同じ組に並ぶ）の後では割らない．Python の括弧外の型注釈（`x: T` / `type A = T` / `x: T = v`）は，注釈の始まりか右辺の前で割る時に型を括弧で包んで折り返す（`item: (` の次の行に `Receiver[int, str]`．値の式は既存の括弧の内側で割る）．型注釈の `:` と初期化子の `=` を直接の子に持つ宣言（Rust の `let` / `const` / `static`，Kotlin の関数の宣言の戻値の型 `fun f(p: T): R = v`．`TypedBinding`）の `:` の後では割らず，仮引数の並びで割る．

#### 3.7.1 Ruby 固有の分割候補制御

Ruby は他言語と異なり以下の制約が有る為，`CollectBreaks` / `SplitSide` で固有処理する：

- **括弧無の `argument_list` / `method_parameters` のカンマ改行抑止**：`puts x, y`（括弧無の呼出）や `def foo a, b` のカンマ後に改行を入れると別の文に分裂し構文崩壊する．第０子が `(` でない `argument_list` / `method_parameters` は全無名を分割対象外．
- **二項演算子の改行後置**：Ruby は行頭の演算子（`\n+` `\n=` `\n?` `\n:` 等）を別の文と解釈する為，`)` `]` `}` `.` `?.` を除く末尾系トークンは改行後置（`expr =\n value` / `cond ?\n a :\n b` 形）に揃える．
- **ヒアドキュメント開始行の分割禁止**：本文は開始トークン (`<<~` / `<<-` / `<<`) の在る行の次行から始まる為，其の行の何処で改行しても本文の起点がずれ，以降の行が別の実引数・別の文として読まれる．`DropHeredocLineBreaks` が開始トークンを含む行の候補を全て落とす（解析器は受理する為，構文守衛では捕捉出来ない）．
- **`rescue` 修飾子の分割禁止**：`x = f rescue 1` の `rescue` 前で改行すると節が独立し構文が壊れる為，`rescue_modifier` は `BreakOpaque` として内部を分割候補にしない．

### 3.8 `ApplyDocComment`

**対象**：C / C++ / Java / Kotlin / PHP / JS / TS / Ruby

関数定義の文書化コメント (Doxygen / JSDoc / KDoc / YARD) を生成・補正する．紐付が有効な状態で `FinalizeLayout` 前に実行する．

- 文書化コメントが無ければタグ骨格（`/**` ... `*/` 又は `# ` 行）を付与する．
- 既存の文書化コメントが有れば不足 `@param` / `@return` を追加し，余分を削除する．説明文は保持する．
- `@return` は値を返す関数に付ける：C / C++ / Java / Kotlin は宣言した戻値の型（`void` / `Unit` 以外），PHP と TS は宣言した戻値の型（`void` / PHP の `never` 以外．無ければ値付の `return` の有無），JS と Ruby は値付の `return` の有無で決める（ネストの関数・ジェネレータ・無名関数・ラムダの中の `return` は数えない．`NodeKind::FunctionLikeAny`）．Kotlin の型を略した式の本体（`fun f() = g()`）は `Unit` を返すかを字面で決めれない為に付けず，Ruby の無終端の定義（`def f(x) = x + 1`）は本体の式の値を返す為に付ける．
- 既存の文書化コメントの `OldLeading` 内位置 (`DocIdx`) を保ち，他の先行コメントとの相対順序を変えない（コメント同士の位置関係の維持）．
- `#` 行で書く言語（Ruby）では，シバン（`#!`）とマジックコメント（`# -*- … -*-` / `# frozen_string_literal: true` / 符号化の指定等）も処理系が読む指令の為，文書化の行へ取り込まず其の儘先頭に置く．
- `#` 行で書く言語（Ruby）では，`#` で始まらない先行コメント（埋込ドキュメント `=begin` 〜 `=end`）を文書化の行へ取り込まず，其の儘先頭に置く（取り込むと `# =begin` と本文が割れて構文が壊れる）．
- `ts_node_has_error(Node)` の関数は引数抽出が信頼出来ない為対象外とする．JS / TS オブジェクトリテラル内の省略記法のメソッド（呼戻関数／インターフェース実装用途）も対象外．
- 錨が行頭でない場合（前段で他メンバと同一行に並んだ Java インターフェースの abstract+default 等）は，先行コメント束縛先が再構文解析で別ノードへ移り非冪等化する為対象外とする．

### 3.9 `FinalizeLayout`

**対象**：全言語（構文解析失敗時も最低限適用）

最終ソースの各行に対し以下を１回の行走査で適用する．

1. **インデント深さ計算**：

	- **ブラケットペアベース** (C / C++ / C# / Java / Go / Rust / Kotlin / Swift / PHP / JS / TS / JSON / HTML / CSS)：`ComputeBracketIndent` でソース中の `()` `[]` `{}` ペアを構築（文字列・コメント内除外）．JS / TS / HTML は更に JSX / HTML タグの仮想ペアを追加．行毎に「先頭バイトより前に開き，先頭バイトより後で閉じる行跨ぎペア」の起点行の重複を除いた個数をインデントとする．行頭が行跨ぎ閉じ括弧／セクションヘッダ（`case`／アクセス修飾子／`goto` ラベル等）なら −1．
	- **AST の深さに基く計算**（Ruby / Python）：`CollectLineIndents` が AST を再帰走査して各行の深さを決定．`IndentBlock` 集合（`block`・括弧付 `argument_list`・Python の組・並びの型（`tuple_pattern` / `list_pattern`）等）・`RubyBlock`・`JsxElement` で +1，`SectionHeader`（`when`・`rescue`・`else`・`ensure`・`elsif` 等）で −1．Ruby の継続構文 (`RubyContinuation`) はノード開始行の既設定インデント + 1 で算出する．Python は関数・クラス・制御構文の本体と継続式の構造から深さを求め，透過的な節点の子や行頭の演算子にも深さを登録する．

2. **タブ変換**：算出した深さをタブで出力．インデントマップに無い行は元の先頭空白を `TabChars + ceil(SpaceChars / IndentChars)` で換算する．此の補助経路の `IndentChars` は全言語で４に固定する．

3. **空行制御**：AST 由来の意味的境界（`RootBlankBefore` 集合）にのみ空行を挿入する．元ソースの空行は引き継がない．閉じ括弧後の `=` 始まり行と Python の `:` 直後では登録済の空行も抑制する．前処理指令系の `#else` 直後にも空行を登録する．

4. **行末空白除去**：各行末のスペース・タブを除去（複数行文字列／ヒアドキュメント本文／HTML の逐語保持要素の内容は逐語保持）．

5. **コメント復元**：`CollectCommentInsertions` で AST ノード位置から (`Leading` / `Inline` / `Trailing`)× `Dest` バイトを求め，行ループに同期して挿入．独立行のコメントは錨と同じインデントに置く．見出しの字句の直後のコメント（`CommentAttach::IsHead`）は錨の前のコードの終わり（錨が行の途中なら錨の行の行末）へ行末コメントとして置く（次の行に作用する指令は，錨が行の途中なら錨の行の行末へ置くと更に次の行へ作用する為，他の先行コメントと同じく錨の行の前へ置く：`if(a) { // @ts-expect-error` の本体を畳んだ `if(a) r = foo("s");` の前）．錨が行の途中の先行コメントは，囲みコメントを錨の直前の行内へ，行コメントを錨の行の前（閉じ括弧で始まる行・Ruby の畳んだ節の行では行末）へ置く．行内へ置いた囲みコメントの後の行コメントは，行の前へ置くと順が入れ替わる為に錨の行の行末へ置き，其の行で其の後に続くコメント（後の錨の物を含む）も続けて行末へ置く．句点で行を分けたコメントを行末へ置く時は分けない本文（`CommentAttach::Joined`．群の中に句点を含むコメントが有れば正規化した全てのコメントに作る）を使う．PHP の地の文の後の開始タグで始まる行（`?>` の次の行の `<?php`．前のインデントは描画される地の文の為に逐語で写す）へ移したコメントは，逐語の行の閉じタグの直前へ差し込む．空の JSX 式のコメントは `{` 直後へ戻し，其の他の JSX 越境コメント（差込先の行頭か錨の直前が JSX の要素の本文に当たる物．外の `{…}` の中の行頭は式の文脈で越境でない）は外側へ退避して本文への混入を防ぐ．行末で行コメントに続くコメントは，単一行の行コメントならコメントの数に依らず原文の順で連ねる（空の塊のコメント：`} catch {} // A // B`）．連結出来ない物（囲みコメント・複数行のコメント）は，行内のコメントを行内の儘にコメントの順も保つ為（§ 1.7），其の行の直後の独立した行へ置き，其の行で其の後に続くコメントも続けて置く（空行を飛ばした次の行が閉じ字句（`NodeKind::CloserToken`）で始まらなければ其の行の先行コメントとし，其の行の構文の先行コメント（自動の文書化コメントを含む）より前へ並べる．次の巡は後の構文の先行コメントと読む為で，文書化コメントの後へ置くと次の巡で其の構文の文書化コメントと読まれる．行の前へ回す行内の行コメントは行末に置かない為に行コメントに数えず，回す判断は行の前へ回した後に行う）．閉じ字句で始まる行の前は直前の括弧の内側で，次の巡で後続の枝や直前の文のコメントへ読み替えられて位置が動く為，閉じ字句と対を為す構文の始まる行まで遡って其の前へ回す．閉じ字句で始まる行では，行の最初の行末コメントも同じ所へ纏めてコメントの並びを保つ．閉じ波括弧で始まる行の行内の行コメントは，行の末尾へ置くと次の巡で閉じ波括弧の後の本体のコメントへ読み替えられる為，閉じ波括弧の直後に節が続けば（`} else` / `} catch`）行の前（手前のブロックの末尾：次の巡も其の節の先行コメントに戻る）へ，続く節が無ければ（`}.map {` 等）閉じ波括弧と対を為す構文の始まる行の前へ回す．但し節の見出しの中のコメント（`} else if(` と条件の間．C# / Go / Kotlin の無名の `else` の後を含む）は，行の前へ回すと手前の塊の末尾のコメントに為る為に行末へ置く（次の巡は見出しの字句の後のコメントとして同じ所へ置く）．差込先が複数行のリテラル（文字列・ヒアドキュメント・Ruby の `%w[...]` 等）の内容に当たるコメントは，本文へ混入すると値に化ける為，其の外の行頭へ移す．Ruby の埋込ドキュメント（`=begin` 〜 `=end`）は行頭から始まる行を占める為，行内の物は其の行の前，行末の物は次の行の前へ回す．

6. **末尾改行**：工程入力の末尾改行を維持．最終出力では非空の整形結果の末尾改行を１つにする．

### 3.10 `Postprocess`

レイアウト確定後，後処理 ERROR ガードの前に以下の最終補修を `TextEdit` 経由で適用する．

- **`KeepEncodingDeclaration`**: Python / Ruby の符号化の宣言（マジックコメント）は先頭２行でのみ効く為，前の空行やコメントが詰まって３行目以降から効く位置へ上がった場合に空行を補って戻す．
- **`FixGoTrailingComma`**: Go の複数行コンテナは末尾 `,` 不在でセミコロン自動挿入に伴う構文エラーに為る為，補修する．
- **`FixCssMissingSemicolon`**: CSS / SCSS はブロック内の最後の宣言で `;` を省ける為，補完して宣言の並びを揃える（規約 2.15・6.16）．
- **`FixHtmlSelfClosing`**: HTML の空要素の自己終端記号 `/` を除去する．外来コンテンツと，内容を文字として読む要素の内側は保持する．外来コンテンツの外で名前空間を宣言する (`xmlns` / `xmlns:接頭辞`) 文書は，空要素も `/` で閉じねば為らない XML 構文 (XHTML) の為，全体を保持する（XML 宣言 `<?xml` で始まる文書は構文解析器が読めず見送る）．
- **`FixJsxEdgeSpaces`**: JSX の本文の端の空白の印を，改行に接する物は `{" "}` へ，接しない物は空白へ戻す．タブの印は改行を詰めて隣の子へ密着させる（§ 3.3）．
- **`TrimTrailingWhitespace`**: 各行末の空白を最終的に除去する（生文字列／ヒアドキュメント／複数行リテラル／PHP の地の文／HTML の逐語保持要素の内容は保護）．

### 3.11 後処理 ERROR ガード

整形完了後の AST で，入力に無かった `ERROR` / `MISSING` が検出された場合は原文返戻する．此の返戻は壊れた出力を利用者へ届けない為の最終防壁で，発火は § 1.1 に反する不具合として扱い，発火させた整形を直す．許容対象の入力破損が有った場合は，破損節点の件数が入力より増えたかで判定する．補修自身が壊した結果も検査対象へ含める為，後処理 (§ 3.10) の**後**，静的検査 (§ 3.12) の**前**に判定する．入力の破損件数は，解析器の読違を揃える前処理（§ 3.1 の Ruby の実引数・JS / TS の `let` の繋ぎ）の前後の少ない方を基準にし，前処理自身が壊した節点も此の防壁で見付ける．

### 3.12 `LintPass::Run`

## 4. 構文解析失敗・エラー時の挙動

### 4.1 原文返戻となるケース

§ 3.1 と § 3.2 のガードに該当する入力は AST 構文解析成功でも整形を行わず原文返戻する．区分「許容」は § 1.1 が許す構文エラーに依る返戻，「対象外」は整形の対象外（対応外の言語と実行環境の限界），「不具合」は発火させてはならない最終防壁である．

| XML の宣言・文書型（`<?xml` / `<!DOCTYPE`）で始まる `.ts`（Qt Linguist の翻訳ファイル） | TypeScript | `XML document` | 対象外 |
| 波括弧の値のカスタムプロパティ（`--x: { a: b }`）を解析器が `--x` を選択子とする規則と読んだ壊れた入力 | CSS / SCSS | `parser could not read the source` | 許容 |
| 引用符の無い `url(…)`（関数名の大小を問わない）を含み，中の `/*` をコメントと読んだ `ERROR`（中身はコメントの形も含む生の字面で，部分整形がコメントを抜いて URL が変わる．コメントの無い物（`url(#mask)`）は ERROR の字面を其の儘写して整形する） | CSS / SCSS | `parser could not read the source` | 許容 |
| 根が `ERROR` の入力（解析器が全体を読めなかった物．部分整形がコメントを規則の外・ファイルの末尾へ移す） | CSS / SCSS | `parser could not read the source` | 許容 |
| 空の仮引数の並び（`@mixin m()` / `@function f()`）へ解析器が補う空の仮引数の MISSING と，`@include m()` の空の実引数の ERROR（何れも正当な Sass） | CSS / SCSS | － | 破損に数えない（`SyntaxCheck::IsToleratedBreak`．mixin の空の括弧は整形が外す） |
| JSX コンテナ内の `ERROR` | JavaScript / TypeScript | `parser could not read the source` | 許容 |
| 演算子へ密着したコメント（`y +/* c */1`）が，読み直す字の数の和が１ MiB に達する個数を超える（解析器がコメントの始まりを演算子の字と読む為，１つ毎に直して読み直す．個数の下限を設けると大きな入力で見送る迄に下限の回数だけ読み直す） | Swift | `comments glued to operators exceed parser limit` | 対象外（読直の費用が入力の大きさに比例する為：`EditPass::ApplySwiftMisreads`） |
| 正規表現の終わりの `/` が逃がされた（前に奇数個の `\` が続く）物（正当な `/a\//` を解析器が `/a\/` で終わると読み，後続を式と読む） | Swift | `parser could not read the source` | 許容（解析器の誤読で，部分整形が正規表現の中身と後続の文を変える） |
| 誤りから立ち直る時に字句を落とした木（子の間に空白と文の区切りの `;` 以外の字が残る物．when の枝の本体の if 式の次の行の `else` を落とし，`"b"↵n + 1` を中置の呼出と読む） | Kotlin | `parser could not read the source` | 許容（解析器の誤読で，部分整形が落とした字句の前後の構文を変える） |
| 最初のコードの後のコメントの並び（コードの行の終わりに続く囲みコメントを並びの始まりに含み，行頭の垂直タブも空白と数え，単独の CR も行を終える（改行の正規化より前に判定する）．Python は行継続の `\` も数え，其れは最初のコードより前でも数える．コードの行から始まる複数行の囲みコメントの中の `//` / `#` で始まる行は，走査器が１つの字句として読む為に数えない（閉じの無い `/*` は，正規表現・JSX の本文・文字列の中の読違で後の並びを見逃さない為に行末で終わった物とする）．複数行の文字列（JS / TS のテンプレート文字列，Python / Kotlin の三重引用符）の中の其の行は，文字列の開きの読違（正規表現・JSX の本文の中の逆引用符）で並びを見逃さない為に数える．JS / TS の式の始まりの `/` は正規表現として行の中で閉じ迄を読み，中の `/*` をコメントと読まない）毎のコメントの数と字の数の積の半分の和が，１億３４２１万と入力のバイト数の１６倍の何方も超える（tree-sitter-python のインデントの走査器と JS / TS / Kotlin / PHP の自動セミコロンの走査器は，改行・コメント毎に後続のコメントを全て読み飛ばして次の字句を求め，並びの長さの二乗の時間を掛ける：１万６千行で十数秒） | Python / JavaScript / TypeScript / Kotlin / PHP | `comments exceed parser limit` | 対象外（解析する前に線形の時間で数えて見送る：`Preprocess::CommentRunSkipReason`） |
| 閉じない文字列（入力途中の `"abc`．引用符で始まるか引用符の字句を直接の子に持つ `ERROR` で，同じ行に閉じの引用符が無い物） | 全言語 | `parser could not read the source` | 許容 |
| 整形後に壊れた節点が増えた (§ 3.11)，又は Ruby の式の接続・Go の自動セミコロン挿入を変えた (§ 3.5 / § 3.7) | 全言語 | 原文返戻 (`Error: formatting would break syntax`) | 不具合 |

軽微な ERROR（構文解析器言語拡張未対応等）は部分整形を許容する．ERROR に接する子の境界は原文の隙間を写し，見出しに ERROR を持つ制御構文は，解析器が後続の文を本体と読み違えた物かも知れない為（Kotlin の `if(x)(r)() else (r)()` の次の行の `while` を本体と読む），ERROR より後の子の境界も原文の隙間を写す（文が１行に繋がらない）．

見送とは別に，整形器が直さず知らせるだけの事実は `[warn]` で出す：BOM の有無 (`File has a UTF-8 BOM`) ・改行様式（`File uses CRLF line endings` / `File uses CR-only line endings; they become LF` / `File mixes CRLF and LF line endings; they become LF outside literals`，リテラルの外の CRLF を揃えた時だけ）・別名との実体共有の切離 (`hard link was broken; the other names keep the old content`)・解析の失敗した範囲を字面の儘写した事 (`Parser could not read part of the source; formatting is partial`)．BOM と改行様式の四件は `--stdin` の経路でも同じ文面で出す（拡張機能の利用者にも知らせる為．別名の切離は書戻の事実で `--stdin` には無い）．名前で除外した経路の数は要約行へ `N path(s) excluded by name` として出す．検査の要約は，全て合格で見送が有る場合に `All checked files conform, N file(s) skipped (not checked), N warning(s)` とし，見送を検査済と読ませない．書込に失敗した場合は `Error writing: <経路>: <理由>` を出す（理由は処理系の誤りの文面．外部の保存との競合や内容の照合の失敗では `the file changed on disk or could not be verified`）．

### 4.2 構文解析失敗時のフォールバック

ガードに該当しなくとも，個別工程がガードに従って動作する．

- **§ 3.3 `AttachComments`**: 構文解析失敗時はスキップ．コメントはソース残置．
- **§ 3.4 `ApplyConsolidated`**: 構文解析失敗時スキップ．HTML は本工程全体スキップ．
- **§ 3.5 `NormalizeStructured`**: ルートが `ERROR` の場合スキップ．
- **§ 3.6 `ApplyVarDeclMerge`**: `IsBraceLang()` 以外，又は構文解析失敗時スキップ．
- **§ 3.7 `LineSplit`**: 構文解析失敗時スキップ．`CollectElseWhileJoins` も AST の閉じ字句だけを結合候補にする．
- **§ 3.9 `FinalizeLayout`**: 構文解析失敗時はインデントマップが空となり，元ソースの先頭空白をタブ換算する退避経路で出力．行末空白除去・空行整理は常に適用．

§ 4.1 の見送時は此の退避経路を使わず原文を保持する．

### 4.3 増分構文解析の自動退避

`TSSource::Reparse` は `IsTreeEdited` の旗有時に増分構文解析を試み，結果に `ERROR` が出た場合は即座に全体構文解析へ退避する．

## 5. 並列化

| 工程 | 並列単位 | 備考 |
|---|---|---|
| `AttachComments` | ルートの直接子毎 | スレッド毎の `Pending` / `DeleteRanges` → 終了後にマージ |
| `ApplyConsolidated` | ルートの名前付子毎 | スレッド毎の `Edits` を合流し，言語別収集器は其の後に逐次実行 |
| `NormalizeStructured` | ルートの名前付子毎 | スレッド毎の `FlatCache` / `StructuredCache` / `ContainsCache` |
| `NormalizeInlineSpaces` | ルートの子毎 | ルートレベル間隙は逐次 |
| `LineSplit::CollectBreaks` | ルートの名前付子毎 | １回目の反復のみ実行（２回目以降は増分更新） |
| `LineSplit::FindCtrlFlows` | ルートの直接子毎 | 反復毎に実行 |
| 静的検査 | ルートの直接子毎 | 部分木毎に１回の `TSTreeCursor` 走査，警告順序は逐次実行と一致 |
| 主処理のファイル整形 | １ファイル／作業スレッド | 不可分操作の計数器で動的取得（LPT スケジューリング） |

スレッド数は `Parallel::DecideThreads(Total, MaxThreads, Threshold)` で決定する．逐次化する仕事数の閾値は既定で `EarlyThreshold = 16`，ファイル単位の処理は１件が重い為 2 を指定する．**ネストの並列実行を禁止**（`thread_local IsInParallelRegion` で検出）し過剰なスレッド起動を回避する．`std::thread` の既定の走脈領域（macOS 512 KB 等）では深い AST 走査で領域が枯渇する為，macOS / Linux は `pthread` と 64 MiB の走脈領域 (`Parallel::WorkerStackSize`) で作業スレッドを起動する．Windows は `std::thread` を使い，実行ファイルの既定の走脈領域（リンカの `/STACK` で 64 MiB）で動作する．

## 6. CLI / API

### 6.1 コマンドライン

```
shavefmt [OPTIONS] <FILE|DIR>...
shavefmt --stdin --lang ID [OPTIONS]
```

| 指定 | 意味 |
|---|---|
| `-w`, `--write` | 変更をファイルに書込（既定では書込無） |
| `-c`, `--check` | 検査のみ（要修正ファイル有時の終了コードは 1） |
| `--diff` | 差分を表示 |
| `-l`, `--lang ID` | 標準入力又は明示ファイルの言語指定（例：typescript, typescriptreact, jsonc．h は `.h` と同じ判定） |
| `-m`, `--chars N` | 行幅上限（非負整数．0 = 無制限．既定：128） |
| `--stdin` | 標準入力から読み込み標準出力へ出力（`--lang` 必須．先頭 BOM は文書の中身の一部としてファイルの経路と同じく戻し，改行の様式は呼出側が持つ為に戻さない：拡張機能は送る前に CR を外し受けた後に戻す） |
| `--no-lint` | 静的検査の警告を省略（高速化） |
| `--fail-on-skip` | 見送りファイルと，シンボリックリンクを経る為に辿らない明示の経路を失敗として数える（終了コード 1） |
| `-h`, `--help` | ヘルプ |
| `-v`, `--version` | 版を表示 |
| `--` | 以降の引数を全て経路として扱う（`-` で始まる名前のファイル） |

`--chars` `--lang` は引数を空白区切で受け取る形式のみ（`--chars=128` 形は非対応）．`--chars` は非負整数として読み取り，負値や非数値は使用法の誤りとして終了コード 2 を返す．

`--lang` は標準入力又は明示指定したファイルへ適用する．既知の拡張子と食い違う指定は拒否し，ディレクトリ配下は各ファイルの拡張子で判定する．`.h` の様に複数の言語が共有する拡張子では指定の言語を其の儘使い（`--lang c` を C++ へ昇格しない），`--lang h` は `.h` のファイルと同じ判定（C として読み，C++ でしか読めない時に C++ へ昇格し，Objective-C は見送る）を求める．VS Code の拡張機能は `.h` の文書に `--lang h` を渡す．

書戻には対応する読込成功を必須とする．同じ親ディレクトリの一時ファイルを同期し，所有者・権限・拡張属性を保持する．POSIX は両名を原子的に交換して交換後の実体を照合し，Windows は付帯ストリームを保持して置換する．競合時は対象名が変わっていなければ戻し，再競合時は退避を残して警告する．macOS の非空 ACL を持つファイルは書き戻さない．

終了コードは 0 が成功（書込・標準入力モードの整形成功と，既定での見送も含む），1 が検査モードの要修正・検査モードで対応するファイルが１つも無い事（書込と既定の試行では 0）・経路の不在・対応外のファイル・読書き失敗・構文守衛に依る差戻・資源不足又は内部の誤りに依る整形の中断・`--fail-on-skip` 指定時の見送り有，2 が使用法の誤り（未知のオプション・値の欠落・排他指定の衝突・`--lang` と拡張子の食違）である．

ディレクトリ指定時は再帰的に走査し，名前で除外する（点で始まる全ディレクトリ，`Carthage` / `Pods` / `bower_components` / `build` / `dist` / `node_modules` / `obj` / `out` / `target` / `vendor` / `venv`，`composer.lock` / `package-lock.json` / `yarn.lock`，`*.min.js` / `*.min.css`）．除外した経路の数は要約行へ `N path(s) excluded by name` として出す．シンボリックリンクは辿らず，走査で出会ったディレクトリ又は対応言語のファイルを指す物の数を `N symbolic link(s) not followed` として出す．明示指定の経路も，何の成分がリンクでも（`link` / `link/` / `link/src/a.c`）辿らずに数える（殻の展開 `src/*` / `packages/*/src` がリンクを経る経路を明示の経路として渡し，木の外の実体を書き換える恐れが有る為．相対の経路は利用者が書いた成分だけを見る．実体を整形するには実体の経路を指定する：macOS の `/tmp` / `/var` は `/private/tmp` / `/private/var` へのリンク）．ファイルを開く時も経路の全ての成分のリンクを辿らない（`O_NOFOLLOW`）．サイズ降順 (LPT) で並列処理する．

### 6.2 環境変数

- `SHAVEFMT_DROP_COMMENTS`（値が `1` の時だけ有効．`0` や空でコメントが消えない様にする）：分離したコメントを書き戻さず，コメント非依存の検査に用いる．`--stdin` の時だけ効き，ファイルを指定した実行は使用法の誤り（終了状態 2）として拒む（書き戻すとコメントが全て消える）．
- `SHAVEFMT_WARNINGS`（任意値で有効）：コメント紐付アンカーが見付からない場合に脱落警告を標準エラー出力へ通知．`std::getenv` の真偽のみで判定し，値の中身は問わない．

## 7. 既知の制約

- **HTML**: 文書型宣言の処理は簡易．埋込 `<style>` 内の SCSS 機能（ミックスイン／ネスト）は tree-sitter-scss の制約で完全には認識されない．
- **C（`--lang c` のみ）**：`NS_BEGIN(x)` 形の名前空間マクロは関数定義と誤読される事が有る．欠落字句が `MISSING` として現れる入力は § 3.2 のガードで原文返戻する．
- **Ruby**: `NormalizeStructured` + `LineSplit` の標準経路に統合済．括弧無呼出のカンマ改行抑止と二項演算子の改行後置で構文崩壊を回避する．ヒアドキュメント本体／正規表現等は `Leaf` としてバイト範囲を逐語保存．
- **Python の版**：出力は原文が読める最も古い版（整形で新しい書き方を持ち込まない：星付の要素を含む添字の組は 3.11，`for` の反復対象の組は 3.9 以降に限る為に括弧を保つ）で読める形に保つ．セイウチ演算子（3.8）等の原文の書き方は其の儘写す．
- **Python / JavaScript / TypeScript / Kotlin / PHP**: tree-sitter-python のインデントの走査器と JS / TS / Kotlin / PHP の自動セミコロンの走査器は，改行・コメント毎に後続のコメントを読み進め，コードの後にコメントが続くと解析の時間が其の数の二乗で膨れる為，手間が数秒を超える並び（短いコメントの行で約５千行）を持つファイルは解析する前に見送る（§ 4.1 の `comments exceed parser limit`）．
- **Kotlin**: tree-sitter-kotlin は if 式の `else` の前の改行を読めず，when の枝の本体の if 式の次の行の `else` を落として前後を読み違える（`"b"↵n + 1` を中置の呼出と読む）為，子の間に字句を落とした木は整形しない（§ 4.1 の `parser could not read the source`）．
- **JSDoc の型の変換**：コメントを整形判断に使わない為，型変換コメントの後の冗長な括弧も通常通り外す．
- **次の行に作用する指令**：整形後の最初の対象行へ移す．行の展開・畳込に依って作用範囲が変わり得るが，コメントの有無で本文の整形を変えない．
- **空の塊のコメントの行末**：空の塊のコメントは構文の最後の行の行末へ連ねる（§ 3.3）為，其の行が後の構文の開き括弧で終わると（`promise.then(() => {}).catch(` の次の行に実引数），コメントが後の構文の見出しのコメントに見える．行の割り方はコメントに依らず（§ 1.2），行内のコメントを独立した行へ出さない（§ 1.7）為である．
- **錨の異なる独立した行のコメントの順**：錨が行の途中へ移る時，囲みコメントは錨の直前の行内へ，行コメントは錨の行の前へ置く（§ 1.7）為，前の錨の囲みコメントより後に書いた別の錨の行コメント（`/** @deprecated */` の `old: 1` と `// 新` の `new1: 2` を１行に畳む）は，行の前へ出て前のコメントより前に為る．囲みコメントを行の前へ揃えると文書化コメントが別の構文へ紐付き，行コメントを囲みコメントへ書き換える事も § 1.7 が禁じる為である．
- **コメントの経路の塊**：経路の塊は半角の字で始まる物（`dir/設定/app.json を読む`）と URL だけを見分ける為，字で始まらない経路（`./設定/app.jsonを読む` / `設定は/usr/local/binに置く`）は後の全角の字との間へ空白を置かずに其の儘写す（`/` の前後の日本語の並列 `可/不可` を経路と読まない為）．
- **Swift**: tree-sitter-swift は見出しの最後の式の後置のクロージャを本体と読む（`if xs.filter() { $0 > 1 }.count > 0 { }`）為，見出しの式を括弧で包んで読み直す（`EditPass::ApplySwiftMisreads`）．其の文を左端に持つ式が後置のクロージャの呼出で終わる形と，見出しの文の直後の同じ行に `{` で始まる塊が続く形（前に文が有る `while xs.contains { $0 > 5 } { break }`）を本体の読違と見分け，其れ以外の読違は扱わない．
